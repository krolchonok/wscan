# Coerce машин проекта

Выбери машину в проекте → `i` → «Coerce / Responder».
Для машины с известным открытым TCP/445 пункт выделяется сразу при входе
из списка хостов. Цель берётся из выбранной машины. Адрес приёмника
по умолчанию — IPv4 этой машины, выбранный ОС по маршруту к цели.
Определение маршрута не отправляет UDP-пакеты. `r` меняет адрес вручную;
ручной адрес сохраняется при повторном открытии окна.

В окне есть действия:

- Запустить/остановить Responder на нашей машине (`p` также переключает).
- Проверить Coerce: приёмник включается автоматически, если не запущен.
- Проверить RPC-интерфейсы без Coerce.
- Выбрать сохранённую учётку (`c`); единственная учётка выбирается сразу.
- Изменить адрес приёмника (`r`). `d` меняет домен учётки, для локальной
  учётки он может оставаться пустым.

↑/↓ выбирают действие, Enter выполняет. Esc отменяет активную проверку
либо возвращает в меню. События приёмника видны в журнале; результаты
проверки и остановленного приёмника сохраняются в «5 Результаты».
Обычно для RPC нужна принятая сервером учётка; отказ anonymous-входа
не означает защищённость от Coerce. Самому приёмнику учётка не нужна.

Проверка списка машин проекта остаётся в «4 Взаимодействие» → AD.
Выбранные машины с открытым TCP/445 используются как цели; если выбора
нет — все машины с TCP/445. `h` задаёт один IP/DNS, пустой ввод возвращает
список проекта. Локальный адрес приёмника пропускается.

## Транспорт и порты

Все реализованные вызовы используют RPC по именованным каналам SMB:

| Метод | Канал | Вызов |
| --- | --- | --- |
| PetitPotam | efsrpc | EfsRpcEncryptFileSrv |
| PrinterBug | spoolss | RpcOpenPrinter + RpcRemoteFindFirstPrinterChangeNotificationEx |
| ShadowCoerce | FssagentRpc | IsPathSupported |
| DFSCoerce | netdfs | NetrDfsRemoveStdRoot для несуществующей шары приёмника |
| MSEven | eventlog | ElfrOpenBELW для несуществующего файла приёмника |

Требуется исходящий TCP/445 к целям и входящий TCP/445 на выбранном адресе
приёмника. TCP/135 и динамические RPC-порты для этих named-pipe реализаций
не используются. NetBIOS TCP/139, UDP/137–138, HTTP/WebDAV и RPC/TCP не
реализованы. Приёмник требует свободный TCP/445 и права ОС на привязку к
этому порту. Программа не меняет firewall или права бинарника. Остановка владельца порта
возможна только после подтверждения в меню.
В папке релиза есть `start.sh`: запустите `./start.sh`.
Он открывает программу от root через sudo, сохраняя текущий
`XDG_CONFIG_HOME` или `$HOME/.config`: используется прежняя база проектов,
настройки и сохранённый путь библиотеки. Если задан `WSCAN_LIBRARY_DIR`,
он также передаётся программе. При `sudo ./start.sh` домашний
каталог исходного пользователя определяется через `SUDO_USER`.
В программе `r` задаёт адрес, `p` запускает приёмник.
Сам скрипт не останавливает службы. Перед запуском приёмника в меню
программа проверяет TCP/445. Если порт занят, показывает PID и имена
процессов и предлагает освободить его: `Enter`/`y` подтверждает, `Esc`/`n`
отменяет. Перед остановкой владельцы порта проверяются повторно.
Управляемая через systemd Samba временно останавливается и восстанавливается
после завершения приёмника или обычного выхода из приложения. Остальным
процессам отправляется SIGTERM; их автоматический перезапуск не выполняется.

Для ручной настройки приёмника можно один раз выдать право
на низкие порты конкретному собранному бинарнику:

```sh
sudo setcap cap_net_bind_service=+ep ./wscan
getcap ./wscan
```

После замены бинарника при обновлении право требуется выдать заново.
Для остановки владельца занятого порта нужны права root: используйте
`./start.sh`. Одного права привязки к низким портам для этого недостаточно.

## Результаты и ограничения

- Проверяются соединение TCP/445, RPC bind и результат RPC-вызова.
- Отдельно сохраняются callback-соединение, SMB negotiation, NTLM negotiate
  и NTLM authenticate с заявленной клиентом идентичностью.
- Authenticate означает получение непустого NTLM-ответа. Пароль/ключ
  неизвестен, поэтому подпись ответа не проверяется и вход не подтверждается.
- Callback относится к адресу цели и временному окну. Асинхронный повтор
  запроса может прийти при следующем методе; точная атрибуция не обещается.
- Отсутствие callback, отказ RPC и несовместимый SMB — неполный результат,
  а не доказательство защищённости. Callback ожидается 1,5 секунды после
  каждого вызова. Последние задержанные callbacks могут не попасть в отчёт.
- Поддерживаются IPv4 и SMB 2.0.2/2.1. Политика SMB3-only или Kerberos-only
  может мешать приёмнику; это не означает отсутствие Coerce.
- Приёмник принимает только адреса выбранных целей; NAT может нарушить
  сопоставление. До запуска DNS разрешается один раз, выбирается первый IPv4.
- Реализованы перечисленные варианты вызовов, а не полный перебор всех
  интерфейсов и методов Coercer. Для большинства методов нужна учётка и
  соответствующие права; anonymous зависит от конфигурации сервера.
- `anonymous-authenticate`: клиент прислал Authenticate без учётных данных;
  это не доказательство утечки. `invalid-authenticate`: повреждённый или
  неполный пакет; эти состояния отображаются отдельно.
- Ответы NTLM, challenge и пригодные для подбора хеши не сохраняются.
  Приёмник завершает вход отказом, не обслуживает шары и не выполняет relay.
- Лимиты: до 4096 целей, 32 соединений приёмника, 64 КиБ на SMB-пакет,
  256 событий на адрес, 12 секунд на соединение. RPC по умолчанию ограничен
  8 секундами на метод; есть дополнительные ограниченные cleanup-вызовы.

Отчёты доступны в «5 Результаты» и `exports/ad/ad-report-*.json` (0600).
Реализация использует Go и уже подключённую библиотеку go-msrpc; внешние
Responder, NetExec, Nmap и Nuclei не запускаются.

Офлайн-проверки: обмен с NTLM-клиентом и SMB2-клиентом через `net.Pipe`,
проверка некорректных NTLM-буферов и недопустимых адресов приёмника.
Полная сборка выполнена. Практический запуск на 10.0.0.10: SMB TCP/445 доступен, anonymous
SMB-вход отклонён. С предоставленной учёткой проверены пять методов;
PetitPotam, PrinterBug и MSEven вызвали обратные SMB-соединения и NTLM negotiate.
Ручная диагностика 11.10.2026 выявила ошибку приёмника: в NTLM challenge
отсутствовал MsvAvNbDomainName. Windows SMBClient/Security сообщал
Smb2DiagReasonISC, событие 31001, статус 0xC000000D. После добавления
NetBIOS AV-пары клиент отправляет Authenticate, но без имени пользователя
и NTLM-ответа: событие `anonymous-authenticate` с информационной серьёзностью.
ПК находится в WORKGROUP (PartOfDomain=False); непустой ответ с учётными
данными не получен. Это подтверждает callback, но не получение доступа.
Сам факт WORKGROUP не доказывает причину каждого анонимного ответа. ShadowCoerce и DFSCoerce: соответствующие именованные
каналы отсутствуют. В ходе теста исправлены ASN.1/SPNEGO negotiation и
UUID для канала efsrpc; EFSRPC-вызов после исправления принят сервером. Приёмник проверен на локальном 10.0.0.16:445; Samba
на время запуска останавливалась и затем была восстановлена.

Форматы SMB: [Microsoft SMB2 Session Setup](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/0324190f-a31b-4666-9fa9-5c624273a694),
[Microsoft SMB2 Negotiate](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/e14db7ff-763a-4263-8b10-0c3944f52fc5),
[Microsoft EFSRPC UUID](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-efsr/403c7ae0-1a3a-4e96-8efc-54e79a2cc451).


CLI без загрузки библиотеки:

```sh
./wscan coerce --targets 10.0.0.10 --discovery
./wscan coerce --targets 10.0.0.10 --callback 10.0.0.16
./wscan coerce --targets 10.0.0.10 --callback 10.0.0.16 --listen --duration 5m
```

`--username` и `--domain` задают учётку; секрет берётся из
`WSCAN_COERCE_PASSWORD` или `WSCAN_COERCE_NTHASH`, без аргумента с паролем.
Отчёт JSON выводится в stdout, события — в stderr. Совместное использование
запущенного приёмника и Coerce поддерживается внутри одного процесса TUI;
два отдельных CLI-процесса не делят приёмник на одном TCP/445.

При входе в AD-проверки из меню конкретного хоста (`i`) этот хост также
сохраняется единственной целью Coerce, а адрес приёмника выбирается по
локальному маршруту. Пустой хост (`h`) включает выбор машин проекта.

Если SMB отклоняет вход ещё до RPC bind, проход останавливается после
первой попытки входа: остальные методы не запускаются, пустые callback
не создаются. В GUI показывается одна сводка «Coerce не проверен — отказ
SMB во входе». Отказ отдельного RPC-канала не останавливает другие методы.

## Диагностика встроенного Responder

В TUI перед запуском приёмника нажми `v` в Coerce / Responder либо AD-меню.
`g` → задача Responder → Enter → `r` открывает журнал; End — последние строки.
Файл журнала находится в каталоге данных wscan: `logs/scan-*.log`.
Для изменения режима работающий приёмник нужно остановить и запустить снова.

CLI использует существующий режим приёмника, без вызова Coerce:

```sh
./wscan coerce --listen --targets 192.168.200.87 \
  --callback 192.168.200.214 --debug --duration 10m \
  --log ./logs/responder-debug.log
```

Адрес callback должен принадлежать машине wscan; TCP/445 должен быть свободен.
Разрешённые источники задаются targets. Соединения вне scope и сверх лимита
32 одновременных соединений отклоняются с диагностикой CONNECTION_REJECTED.
CLI выводит диагностические события в stderr, итоговый прежний AD-отчёт в
stdout; `--log` сохраняет только поток диагностических сообщений. Отчёт может
содержать заявленную клиентом идентичность; диагностический журнал её не содержит.

По умолчанию видны подключение, получение Authenticate, ошибка/отказ и закрытие.
В debug добавляются согласование SMB, типы NTLM, отправка challenge, пустые
поля и этапы SESSION_SETUP. События содержат UTC-время, connection ID, IP:порт,
диалект, последнее обработанное состояние и NTSTATUS (число + имя). Длины
NTLM-полей — байты, presence означает ненулевую объявленную длину; некорректные
security buffers дополнительно отмечаются PROTOCOL_ERROR. Значения полей,
пароли, challenge, NTLM Response и хеши в диагностике не записываются.

Встроенный сервер не проверяет пароль и не принимает SMB-сессию: прежний
ответ на Authenticate — `0xC000006D STATUS_LOGON_FAILURE`. Поэтому получение
Authenticate не означает AUTH_SUCCESS. Пустой ответ помечается
EMPTY_NTLM_RESPONSE; анонимная форма запроса — ANONYMOUS_AUTH_ATTEMPT, затем
AUTH_FAILED. ANONYMOUS_AUTH для установленной сессии здесь не используется.
Реальное отличие от STATUS_ACCESS_DENIED в стороннем Responder видно по коду.

Закрытие содержит известную причину (PEER_EOF, PEER_RESET, IO_TIMEOUT,
SERVER_CANCELLED, SERVER_REJECTED_AUTH, ошибка протокола) либо UNKNOWN.
После отказа сервер сразу закрывает соединение; последующий клиентский LOGOFF
может не быть прочитан. Поведение аутентификации этим изменением не менялось.
История в памяти ограничена последними 256 диагностическими событиями на
хост; живой вывод и файл продолжают получать события после этого лимита.

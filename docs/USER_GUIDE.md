# wscan: что делать и куда нажимать

Эта инструкция описывает текущий TUI и Web. Это карта доступных действий,
а не обещание, что любое действие проверено на настоящем AD-стенде.

## 1. Запуск и выбор интерфейса

```sh
./wscan --web   # браузер + TUI, один процесс и общие задачи
./wscan serve   # Web без терминального интерфейса
./wscan         # только TUI
```

В `--web` открывается браузер и экран «Web готов» с полной ссылкой.
Если браузер не открылся, скопируйте ссылку. `o` повторяет открытие,
Enter переводит в TUI. Из списка проектов или обзора `w` возвращает ссылку.
В `serve` ссылка остаётся в обычном выводе терминала.

Открывайте полную ссылку, включая `#token=…`, при первом подключении.
После входа браузер очищает адрес и сохраняет сессию. Сервер слушает loopback:
браузер должен работать на той же машине. Второй процесс с той же базой
не запускается; используйте существующий процесс.

В Web слева выберите проект; разделы: «Обзор», «Хосты», «Результаты»,
«Задачи», «Доступы», «Как пользоваться». В TUI ↑/↓ выбирают пункт,
Enter открывает его, Esc возвращает назад, `?` показывает помощь экрана.
Ctrl+C завершает приложение, сервер и задачи.

## 2. Первый проект и первый результат

### Web

1. «Создать проект» → название → область: IP, имена хостов, URL или CIDR
   через пробел → «Создать проект».
2. В «Обзоре» проверьте область. Для ещё одного адреса: «Добавить цель».
3. «Начать проверку» → проверьте адреса → «Продолжить».
4. Выберите «Поиск портов и сервисов». При необходимости раскройте
   «Дополнительные параметры» и укажите отдельные TCP-порты через запятую.
5. «Продолжить» → проверьте сводку → «Запустить проверку».
6. В «Задачах» смотрите этап и прогресс; «Подробности» открывают журнал.
7. «Хосты» → «Открыть» рядом с адресом → увидите порты и сервисы.
   «Действия» рядом с сервисом открывают доступные операции.

Ожидаемый результат: список реально найденных сервисов. Отсутствие портов
не доказывает, что хоста нет: проверьте выбранные порты, маршруты и VPN.

### TUI

1. В списке проектов `n` → введите название → Enter.
2. Выберите проект ↑/↓ → Enter. Откроется «Обзор проекта».
3. «Открыть хосты» → `a` → введите цель → Enter. Повторите для второго хоста.
4. `0` → «Начать проверку…» → Enter.
5. Если область уже заполнена, выделено «Продолжить →»: Enter.
   Для изменения ↑ → Enter → отредактируйте адреса через пробел → Enter.
6. Выберите «Поиск портов и сервисов» → Enter → сводка → Enter запускает.
7. `3`/`g` → выберите задачу → Enter для итога; `r` раскрывает журнал.
8. `2` → ↑/↓ выберите хост. ←/→ или Tab переключают панели.
   В панели портов ↑/↓ выбирают сервис, Enter открывает действия.

## 3. Какой профиль нужен

| Профиль | Когда выбирать | Что выполняется | Что нужно заранее |
|---|---|---|---|
| Поиск портов и сервисов | Ещё неизвестно, что доступно | TCP discovery и идентификация сервисов | Цели проекта |
| Аудит AD без учётки / Аудит AD | Нужны домены, DC и Windows-службы | AD/Windows-порты → LDAP → DNS → доступные SMB/RDP сведения → сводка | IP, имена хостов или частные IPv4 CIDR; URL сюда не подходит |
| Обнаружение и проверки проекта | Нужен discovery с последующими проверками | Найти сервисы, затем выполнить выбранные проверки | Цели и выбранные проверки; без проверок будет только discovery |
| Проверки известных сервисов | Порты уже найдены | Выбранные проверки по сохранённым сервисам | Найденные сервисы и выбранные проверки |

Проект с двумя IP не требует превращать их в CIDR. В AD-профиле будут
проверены эти хосты. Имя хоста разрешается через DNS. Адреса из AD SRV-ответов
не расширяют область автоматически. Признак по порту/DNS отделяется от
LDAP-подтверждения DC. Отказ LDAP или достижение лимита сохраняются как
ограничения покрытия, а не успешная проверка.

## 4. Выбор проверок и повторный запуск

**Web:** «Обзор» → раскройте «Проверки проекта» → «Выбрать проверки» →
поиск по сервису/имени → отметьте нужные строки → «Сохранить выбор».
Затем «Начать проверку» → «Проверки известных сервисов» или
«Обнаружение и проверки» → сводка → запуск.

**TUI:** `0` → «Выбрать проверки проекта» → Enter. Выберите группу,
Enter/→ откроет её, Space отмечает проверку. `1`/`2`/`3` внутри каталога
меняют группировку: тип / продукт / сервис; `/` — поиск, ←/Esc — назад.
Выбор сохраняется в проекте. Вернитесь в обзор и запустите нужный профиль.
Альтернативный вход: `2` → `t`.

Чтобы проверить один найденный порт в TUI: `2` → выберите хост →
перейдите в панель портов → выберите сервис → Enter → «Проверки на этом
порту…» → выберите проверки → сводка → запуск. Новые порты в этом режиме
не ищутся. Настройки скорости для разового запуска доступны в расширенной
сводке; в обычном мастере используются настройки проекта.

Если каталога нет: `wscan library update`. Через TUI: Esc до проектов →
`p` → «Библиотека шаблонов» → Enter → Enter скачать/обновить.
Нативной кнопки обновления библиотеки в Web сейчас нет; используйте терминал
сервера или «Полный TUI в браузере».

## 5. Задачи, отмена и результаты

| Действие | Web | TUI |
|---|---|---|
| Посмотреть этап/журнал | Задачи → Подробности | `3` → задача → Enter → `r` |
| Остановить задачу | Задачи → Остановить | `3` → задача → `x` |
| Найти результат | Результаты → поиск → наблюдение | `5` → `/` поиск → Enter |
| Показать AD-наблюдения уровня info | Результаты, без фильтра важности | `5` → `f` → выбрать фильтр со всеми наблюдениями |
| Прочитать доказательство | Наблюдение → Доказательство | Карточка → Tab → Доказательства; `r` технический отчёт |
| Открыть хосты после discovery | Хосты | Итог задачи → Enter |
| Вернуться к обзору | Обзор | `0` из основных разделов |

Закрытие вкладки не отменяет сканирование. При новом подключении задачи
снова видны. Завершение процесса останавливает выполнение. После аварии
незавершённые задачи отмечаются прерванными; автоматического продолжения нет.
История сохраняется в SQLite. Очистка списка завершённых задач в TUI (`c`)
не заменяет удаление истории запусков.

**Экспорт Web:** «Результаты» → выберите запуск и JSON/HTML/CSV →
«Экспорт запуска». При «Все запуски» экспортируется последний запуск,
а не объединение всей истории. Файл скачивается браузером.

**Экспорт TUI:** «Задачи» → выберите задачу с сохранённым запуском → `e`.
CLI с явным форматом: `wscan export PROJECT_ID RUN_ID json|html|csv OUTPUT_PATH`.

## 6. Учётки, скорость и разрешения

**Web:** «Доступы» → «Добавить учётку» → тип, домен, имя, пароль/NTLM-хеш →
«Сохранить учётку». Список не показывает секрет. «Настройки проекта» справа
вверху задают скорость, параллельность, таймаут, повторы и лимиты ошибок входа.
Раскройте «Разрешения расширенных действий», если нужное действие их требует.

**TUI:** `0` → «Учётные записи» → Enter → `a` → тип → ввод полей по очереди.
Enter/`e` на существующей строке редактирует её, `d` удаляет с подтверждением.
В формах подключения `c` открывает выбор/создание учётки. Настройки:
`0` → «Настройки проекта»; в хостах также `p`.

Сохранение учётки само по себе не запускает попытку входа. Настройки проекта
отдельно разрешают проверки учёток, активные проверки/команды и выполнение
code-шаблонов на машине сканера. Ограничение ошибок входа действует там,
где операция использует общий учёт попыток; старые NSE-режимы могут иметь
только лимит внутри запуска. Подробнее: [SUPPORTED.md](SUPPORTED.md).

## 7. Проводники, базы данных и расширенные действия

Единый вход TUI: `2` → выберите хост/сервис → `i` → выберите инструмент → Enter.
Другой вход: `4` → Взаимодействие; `h` выбирает машину.
В Web нажмите «Полный TUI в браузере», выберите проект → Enter → `4`.
Нажмите внутри терминала для ввода. Экранные стрелки и кнопка передачи текста
помогают при работе с телефона. Это тот же TUI; не отдельные веб-консоли.

| Инструмент | Следующий шаг | Результат/границы |
|---|---|---|
| SMB | Выберите null/guest или учётку (`c`), порт (`p`), Enter | Шары и файлы; Enter открыть, ← назад, `d` скачать, `e` CSV, `f` поиск конфигураций |
| FTP/FTPS | Выберите учётку/anonymous; `s` режим TLS, `p` порт, Enter | Каталоги и файлы; Enter открыть, `d` скачать, `p` путь, `e` CSV |
| WinRM | Выберите учётку, HTTP/HTTPS и порт → Enter | Файлы, права и доступные команды; `d` скачать, `a` ACL, `c` команда, `s` PowerShell-сессия |
| MSSQL | Выберите учётку/домен и порт → Enter | Аудит и SQL-сессия; `1`–`8` аудит, `b` база, Enter меню, `c` SQL batch |
| PostgreSQL | Откройте форму и задайте подключение | Базы, чтение таблиц, SQL; доступ зависит от выбранной учётки |
| MySQL / MariaDB | Откройте форму и задайте подключение | Базы, таблицы, чтение и SQL; доступ зависит от выбранной учётки |
| Web: каталоги/файлы | Задайте URL и словарь в форме | Найденные HTTP-пути и ответы |
| Web LFI / SQLi / Upload | Выберите отдельную форму, проверьте параметры и разрешение | Результаты конкретной активной проверки; эти действия не входят автоматически в discovery |
| SSH: словарь | Выберите отдельный режим и списки | Проверки входа; это отдельная операция, не часть поиска портов |
| Kyocera | Выберите адрес и порт → запуск в форме | Данные адресной книги, если устройство позволяет чтение |
| CVE: офлайн | Выберите «CVE — офлайн» | Сопоставление сохранённых версий; совпадение версии не доказывает эксплуатацию |
| NSE vuln | Выберите режим и набор проверок | Активные совместимые проверки; требуют соответствующих разрешений |
| AD Scan | Откройте старую форму выбора сети | Отдельный проход подсети; для двух хостов удобнее мастер проекта |
| AD: учётки/Kerberos/SYSVOL | Выберите машину/учётку и отдельную операцию | Доступные AD-чтения и проверки; условия показываются в форме |
| Coerce / Responder | Откройте отдельную форму выбранной машины | Активный сценарий с отдельными параметрами и разрешениями, не автоматический этап AD-разведки |

В обычном Web «Хосты» → адрес → сервис → «Действия» даёт доступ к части
LDAP/SMB/WinRM/MSSQL-модулей. Учётку добавьте заранее; оставшиеся действия
открываются через встроенный TUI. Если модулей нет, «Открыть проверки» ведёт
в каталог проекта.

Скачивания через TUI сохраняются на машине сервера, в каталоге конфигурации
wscan (`downloads`), а не в папке загрузок браузера. Подробные инструкции
по WinRM/MSSQL/FTP и ограничениям: [README](../README.md),
[SUPPORTED.md](SUPPORTED.md), [BLOODHOUND.md](BLOODHOUND.md).

## 8. Удаление, перенос и диагностика

- Удалить хост/порт: TUI `2` → выбранный хост или порт → Del → подтвердить.
  История старых запусков остаётся отдельно от рабочего списка.
- Удалить проект: список проектов → Del → подтверждение. Нативной кнопки
  удаления проекта в Web пока нет; действие есть во встроенном TUI.
- Перенос: закройте процесс и перенесите каталог конфигурации с базой и
  библиотекой. Для Linux обычно `~/.config/wscan/`. [TRANSFER.md](TRANSFER.md).
- «Нет известных сервисов»: сначала выполните поиск портов.
- «Проверки не выбраны»: откройте каталог проекта, отметьте проверки.
- «Ничего не найдено» в TUI после AD: переключите фильтр результатов на все.
- Отказ доступа: откройте журнал; проверьте учётку, протокол, порт и права.
- Нет браузера/графической сессии: используйте ссылку на машине сервера или TUI.
- Зависимости Python/Ruby: список проектов → `p` → «Зависимости: Python и Ruby».

## 9. Что проверено по UX

Проверка выполняется локально, с временной базой и loopback-сервисами.
Пройденные сценарии и найденные ограничения: [UX_REVIEW.md](UX_REVIEW.md).
Реальные AD/SMB/WinRM/SQL-сервисы в этой проверке не запускались.

# Универсальная первичная AD-разведка

Реализовано в `internal/adscan.Discover`, используется текущим TUI.
Последовательность: AD/Windows TCP-порты → LDAP/LDAPS RootDSE → DNS SRV →
связь имён с найденными IP → существующие SMB null/guest, AS-REP и SMB/RDP-проверки →
сохранение сведений, источников и сводки в проект.

В меню проекта выберите «3 AD-разведка → Разведка AD». Область может содержать
несколько IP, имён хостов и частных IPv4 CIDR. Отдельный IP проверяется
как один хост; адреса не заменяются охватывающей подсетью.

В списке проектов нажмите `d`. Выберите подсеть стрелками; Enter запускает проход.
«Ввести подсеть вручную» сначала добавляет CIDR: затем Enter запускает выбранную сеть.
В открытом проекте AD-разведка доступна через раздел «AD-разведка».
`p` переключает сохранение в текущий/новый проект. После запуска параметры захвачены
задачей; `x`/Esc отменяет её. Общий экран задач доступен через существующую навигацию.

Для VPN или закрытого LDAP: `a` раскрывает дополнительные параметры;
`d` задаёт дополнительные DNS (IP или IP:порт через запятую),
`n` — дополнительные DNS-имена доменов, `b` — лимит SRV-запросов.
Пустой ввод DNS/доменов очищает ручные значения. Они дополняют найденные сведения
и действуют для текущей формы запуска. По умолчанию 1024 SRV-запроса,
64 ответа на запрос, до восьми параллельных запросов.
Лимит не обрезает список до четырёх доменов/серверов; при его достижении
показывается неполное покрытие. Для связи SRV-имён с IP читаются A/AAAA,
до 256 уникальных пар DNS/имя. Адреса вне области не добавляются в сканирование.

«Контроллер домена» подтверждается LDAP RootDSE: есть домен, hostname и AD capability
`1.2.840.113556.1.4.800`, отсутствует AD LDS capability `1.2.840.113556.1.4.1851`.
Порты Kerberos + LDAP или DC SRV дают «Предполагаемый контроллер домена».
Само имя узла, домен или подпись SMB не подтверждают DC.
Остальные роли по портам остаются предварительными признаками.
[Описание capabilities Microsoft](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/3ed61e6c-cfdc-487d-9f02-5a3397be3772).

Идентификация сохраняет источник каждого LDAP/DNS-факта; DNS не заменяет уже
прочитанное LDAP-имя/домен. Отказ чтения LDAP-пользователей не теряет RootDSE.
Пропуски DNS, таймауты и лимиты видны в журнале и сохранённой сводке.
SRV — объявление в DNS, а не проверка работоспособности конечного сервиса.
Система не правит hosts/krb5.conf и не использует имена/пароли из GOAD.

Это первичный проход, а не вся дорожная карта автоматизации. SMB/RDP-результаты
сохраняются существующими проверками, но пока не являются структурированным входом
доменных DNS-запросов. Полный поиск портов, проверки с учёткой и продолжение после
перезапуска находятся в [плане](AUTOMATION_UI_WEB_PLAN.md).

## AS-REP без пароля

При открытии «Учётки, Kerberos, SYSVOL» домен и LDAP-контроллер подставляются из
данных проекта. В нескольких доменах используется домен выбранной машины;
без такого контекста показывается список доменов для ручного выбора.
Если данных ещё нет, фоном читается только RootDSE известных LDAP-узлов:
до восьми узлов, четыре параллельно, до шести секунд суммарно, без bind и списка
пользователей. Определённый контроллер используется и при переходе к AS-REP.
Ручные изменения и смена проекта отменяют применение устаревшего ответа.

Чтобы назначить контроллер вручную, откройте «3 AD-разведка → Контроллер домена:
выбрать машину». Стрелки и Enter выбирают любой отдельный ПК проекта (IP и имя),
даже если сканер ещё не подтвердил DC. В «Проверки AD» этот список открывает `h`,
в форме AS-REP — строка KDC. Назначение сохраняется отдельно для каждого проекта,
переживает перезапуск и не заменяется автоопределением. Известное доменное имя
подставляется; иначе читается RootDSE выбранной машины или имя задаётся через `d`.
Есть пункты «Автоопределение контроллера» и «Ввести IP/DNS вручную».
Ручное назначение не изменяет результат LDAP-подтверждения роли DC.

AD-проход объединяет собранные LDAP-имена по доменам и запрашивает AS-REP без
pre-auth у одного обнаруженного KDC TCP/88 в выбранной области. Адреса SRV вне
области не опрашиваются. Нет домена, KDC или имён — явный пропуск, а не отсутствие
уязвимости. При отказе anonymous LDAP имена нужно предоставить отдельно.

Меню: «3 AD-разведка → Учётки, Kerberos, SYSVOL → AS-REP без пароля → Hashcat».
Форма управляется стрелками и Enter: домен, KDC, пользователи, запуск, назад.
Домен/имена/DC берутся из проекта, включая данные после перезапуска.
Можно указать имена через пробел/запятую или `@/путь/users.txt` (один пользователь
на строку; до 5000 строк и 1 МБ). Пустой список включает автоматический сбор.
Если KDC не обнаружен в проекте, отдельное действие ищет `_kerberos._tcp` через
заданные DNS либо системный resolver; хост можно задать вручную.

Запросы выполняются собственным Go-кодом; пароль, NTLM-хеш и выбранная учётка
не используются. RC4 сначала, AES128/256 при `KDC_ERR_ETYPE_NOSUPP`; каждый запрос
учитывает RPS проекта (по умолчанию 5/с). Сетевые ошибки и неполный LDAP-список
показываются отдельно. Pre-auth required, неизвестное имя и отключённая/заблокированная
учётка не считаются уязвимостью; обычные ответы объединены в одну сводку.

Подтверждённый ответ сохраняется в результатах проекта с привязкой к KDC.
Hashcat-файлы находятся в `exports/ad` каталога wscan (0700/0600 на Unix).
Это зашифрованный AS-REP для офлайн-проверки пароля: ключ сессии не расшифровывается,
пригодный для входа `.ccache` не создаётся. Пароли не перебираются.
При отмене уже полученные ответы сохраняются.

Проверены локальные KDC/DNS fixtures: RC4/AES, отказ pre-auth, неизвестное имя,
блокировка, несовпадающие identities, повреждённые пакеты и отмена.
На живом AD/GOAD этот этап пока не проверялся.
Формат сверялся с [Impacket GetNPUsers](https://github.com/fortra/impacket/blob/master/examples/GetNPUsers.py).

## Проверки Windows в AD-проходе

| Служба | Проверки |
| --- | --- |
| SMB 445 | MS17-010 / EternalBlue, DoublePulsar, диалекты, подпись, ОС/домен |
| SMB 139 без 445 | NSE MS17-010, DoublePulsar и сведения SMB |
| RDP 3389 | MS12-020, BlueKeep, NTLM-метаданные |
| Подтверждённый LDAP DC с RPC 135 | Zerologon, без изменения пароля машинной учётки |
| SMB 445, включены активные проверки проекта | MS08-067, MS10-061, SMBGhost |

MS12-020 непосредственно проверяет CVE-2012-0152; связь с CVE-2012-0002 — общее
обновление, а не отдельная проверка RCE. MS10-061 требует общей папки принтера
и отправляет тестовое задание печати. MS08-067 может обрушить службу; существующий
шаблон SMBGhost отправляет некорректный сжатый пакет. Эти три проверки сохраняют
ограничение `AllowExploit`, включая запуск через AD.

MS06-025, MS07-029 и MS10-054 в библиотеке проверяются через сбой службы.
Автоматический AD-проход их пропускает согласно политике отключённых DoS-проверок.
Причина сохраняется в сводке. Положительные результаты привязаны к IP и порту
и относятся к одному AD-запуску; MS17-010 не дублируется между NSE и Go.

Если `smb-protocols` подтвердил отсутствие SMBv1, MS17-010 на этом хосте не
запускается. Если `rdp-ntlm-info` вернул Windows 6.2 или новее, MS12-020 и BlueKeep
пропускаются как не относящиеся к этой версии. Неизвестная версия ОС или ошибка
получения диалектов не подавляет проверки. Отсутствие доменного имени для DNS SRV
сохраняется как пропуск; настоящие сетевые ошибки остаются ошибками.
[Затронутые версии BlueKeep](https://www.microsoft.com/en-us/msrc/blog/2019/05/prevent-a-worm-by-updating-remote-desktop-services-cve-2019-0708),
[версии MS12-020](https://learn.microsoft.com/en-us/security-updates/securitybulletins/2012/ms12-020).

RDP реализован внутри wscan: полные TPKT/MCS-пакеты, TLS и старое RC4-шифрование
40/56/128 бит. Для BlueKeep отправляются только проверочные MS_T120 PDU штатного
размера. NLA, таймаут, закрытие соединения и неподдерживаемая схема сертификата
означают неполную проверку, а не подтверждённое отсутствие уязвимости. В частности,
BlueKeep остаётся неопределённым, если старый XP-сервер не завершил licensing или
не прислал Demand Active/Font Map. Наличие SMB 3.1.1 само по себе не считается SMBGhost.

Проверены локальные протокольные fixtures: MS12-020 с исправленным/уязвимым ответом,
BlueKeep через TLS и без шифрования, RSA/RC4 и подписи сообщений, NLA, повреждённые
пакеты и отмена. На настоящих Windows XP/7/Server эти новые проверки пока не проверялись.
Протокол BlueKeep сверялся с [проверкой Rapid7](https://github.com/rapid7/metasploit-framework/blob/master/modules/auxiliary/scanner/rdp/cve_2019_0708_bluekeep.rb),
MS12-020 — с [Nmap](https://nmap.org/nsedoc/scripts/rdp-vuln-ms12-020.html).
Для адаптированных RDP capability-данных сохранена [лицензия](licenses/METASPLOIT_RDP.txt).

Проверки используют локальные LDAP/LDAPS/DNS-серверы и TUI fixtures;
на реальных целях или GOAD при этой реализации проход не запускался.

# Пробелы по результатам сетевого теста

Обновлено 2026-10-13. Основные проходы выполнены движками wscan: AD discovery,
TCP Top 1000 с определением служб, NSE, HTTP-шаблоны, SMB browser, SYSVOL, AS-REP.
Внешние инструменты использованы только для проверки результатов или отсутствующих
возможностей. Сетевые отчёты и база проекта хранятся отдельно от репозитория.

## Исправлено в текущем изменении

| Проблема | Исправление и проверка |
| --- | --- |
| TLS-сигнатура превращала RDP в HTTPS | TLS сохраняет известный протокол; HTTPS требует HTTP-сигнатуру. Повторный сетевой проход больше не отправляет RDP в Web. |
| RPC over HTTP считался обычным Web | `ncacn_http` / `rpc-http` исключены из HTTP discovery и Web URL. Повторные HTTP-проверки проходят без этих таймаутов. |
| `ftp-anon.nse` падал в `ftp.connect` | Добавлен `stdnse.make_buffer`, включая уже прочитанный баннер и многострочные ответы. Проверены локальный FTP и повторный сетевой запуск. |
| Название SMB-находки подразумевало файловый доступ | Указано именно перечисление ресурсов; чтение/запись из него не следуют. |
| Локальные учётки и валидный вход | Добавлены local-only SMB с отдельными лимитами, нормализованные passpolicy/PSO, Windows/WDigest/сеть/DNS и OpenWrt post-auth; [описание](LAB_COVERAGE.md). |
| SMB identity, доступ и SAMR | NTLM identity сохраняется с источником, read/unknown/errors SMB-шар не теряются, встроенный SAMR сохраняет отказ и передаёт разрешённые доменные имена в AS-REP. LSA RID-перебор остаётся отдельной задачей. |
| Headless AD и матрица покрытия | `--help`, `ad-scan`, `audit`, `local-smb`; статусы проверок по узлам, включая incomplete/denied/disabled вместо ложного negative. |

## Следующие задачи

| Приоритет | Задача | Наблюдение / критерий готовности |
| --- | --- | --- |
| P1 | Быстрый обход CIDR без host discovery | Сейчас адреса сканируются последовательно, а таймауты повторяются для каждого порта каждого молчащего адреса. Нужны общий ограниченный пул, единый RPS и общий прогресс; `-Pn` должен сохранять охват всех адресов. |
| P1 | Ранняя отмена discovery | Поздняя отмена AD/NSE и authenticated-аудита теперь сохраняет выполненные проверки. Ещё нужно сохранять частичную инвентаризацию при отмене самого discovery. |
| P2 | Структурированная RDP identity | SMB NTLM identity уже сохраняется. Дополнить единый формат данными RDP и проверить противоречащие источники. |
| P2 | SMB integrity | При первоначальном повторе наблюдался `unverified packet returned`; ошибки теперь сохраняются, нужна отдельная воспроизводимая проверка srvsvc/SMB integrity. |
| P2 | Продолжение по найденным службам | Предлагать подходящие проверки Elasticsearch, GlassFish, FTP и MySQL после обнаружения версии, без запуска неподходящих HTTP-проверок по RDP/RPC. |

## Дополнительные направления для этого стенда

- **Elasticsearch MVEL / CVE-2014-3120:** версия 1.1.1 и API без авторизации
  дают основание проверить dynamic scripting. В библиотеке уже есть
  `http/cves/2014/CVE-2014-3120.yaml`, но его команда и matcher рассчитаны на Linux
  (`/etc/passwd`); обнаруженный сервер работает на Windows. Нужна совместимая
  проверка с явным включением активных действий, без вывода «не уязвим» по
  несовпадению Linux-маркера. Требования к scripting и данным индекса ещё не проверены.
  [Описание модуля Rapid7](https://www.rapid7.com/db/modules/exploit/multi/elasticsearch/script_mvel_rce/).
- **GlassFish admin / deployment:** обнаружен порт 4848 и GlassFish 4.0.
  Сейчас есть fingerprint стандартной страницы, но нет отдельной цепочки проверки
  административного доступа и deployment. Для RCE требуется доступ к admin-интерфейсу
  и соответствующая авторизация; fingerprint не подтверждает обход входа.
  [Описание модуля Rapid7](https://www.rapid7.com/db/modules/exploit/multi/http/glassfish_deployer/).
- **MS17-010 exploitation:** wscan подтвердил уязвимость на двух машинах, но
  нативного получения сессии через EternalBlue нет. Это отдельный режим эксплуатации,
  не ещё одна строка в discovery.
- **Coercion → NTLM relay:** Coerce и локальный приёмник уже есть, relay не
  реализован. На двух Windows-клиентах SMB signing не обязателен — кандидат для
  проверки, но нужны подходящий входящий NTLM и права этой учётки на конечной машине.
  LLMNR/NBT-NS poisoning требует подходящего сегмента: текущий сканер находится
  за маршрутизатором, а не в том же broadcast-домене, что цели.
  [SMB signing и relay, Microsoft](https://learn.microsoft.com/windows-server/storage/file-server/smb-security-hardening).

## Контрольные результаты

- MS17-010 совпал у wscan и Nmap на двух узлах; на третьем подтверждения нет.
- MS12-020 повторился в нативной проверке дважды. Внешняя NSE-проверка зависла
  на handshake, поэтому независимого подтверждения этой находки пока нет.
- AS-REP на настоящем KDC корректно различил pre-auth required, disabled principal
  и неизвестное имя. Положительный AS-REP в этом стенде не получен; его формат
  остаётся проверенным локальными RC4/AES fixtures.
- Перечисление SMB-ресурсов удалось без пользовательской учётки, чтение файлов
  не подтвердилось. SYSVOL/NETLOGON получили отказ.
- Elasticsearch раскрыл версию без авторизации, GlassFish и MySQL определены
  штатными проверками. Команды на целях и эксплуатация RCE не выполнялись.

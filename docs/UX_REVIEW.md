# Локальная проверка UX

Проверены маршруты открытия проекта, запуска и отмены задачи, просмотра
сервисов и результатов. В TUI проверяется видимость выбранного действия
и кнопки запуска всех профилей на терминале 55×18. Основной рекомендуемый
размер для ручной проверки — 100×24 или больше.

Исправлено:

- AD-профиль принимает список IP/имён хостов; два хоста не требуют CIDR.
- Подсказка Web не скрывает клавишу создания проекта в TUI.
- Нижние пункты обзора прокручиваются; выбранное действие остаётся видимым.
- Заполненная область мастера сразу предлагает продолжить.
- Выбор проверок проекта доступен из обзора.
- Пустой набор проверок объясняется до создания фоновой задачи.
- Пользовательские порты полного профиля передаются исполнителю.
- В Web исправлен экспорт последнего запуска и переход сервиса в каталог.
- В Web появились инструкция и выбор JSON/HTML/CSV для экспорта.

Браузерный сценарий проверяет временную базу, локальный HTTP-сервис,
AD-запуск по двум loopback-адресам, отмену и повторное подключение,
экспорт, настройки, учётки и встроенный TUI. Повторить:

```sh
go build -o /tmp/wscan-ux .
WSCAN_TEST_BINARY=/tmp/wscan-ux python3 scripts/check-web-ux.py
```

Для сценария нужны Python, Playwright и Chromium. Артефакты сохраняются
в `/tmp/wscan-web-ux`; каталог можно изменить через `WSCAN_UX_ARTIFACTS`.

Остаются ограничения:

- Нативные Web-проводники/консоли заменяются встроенным TUI.
- На мобильном Web часть разделов находится в горизонтальном меню.
- После закрытия встроенного TUI возможна устаревшая ошибка опроса сеанса.
- Реальные AD/SMB/WinRM/SQL-подключения этим UX-прогоном не проверялись.

Сейчас пользовательская ручная проверка выполняется только в обычном TUI.
Маршрут и ожидаемые результаты: [USER_GUIDE.md](USER_GUIDE.md).

# TUI и Web в одном процессе

Из рабочего репозитория `sources/`:

```sh
go build -o ../wscan-web .
../wscan-web --web
```

`--web` запускает сервер, автоматически открывает браузер и показывает
экран с полной ссылкой. Enter переводит в TUI; `w` из проектов или обзора
снова показывает ссылку, `o` повторяет открытие браузера. Только браузер:

```sh
../wscan-web serve --listen 127.0.0.1:8080
```

Откройте полную ссылку `Web:` из терминала. Одноразовый токен находится во
фрагменте URL; после подключения адрес очищается, браузер получает локальную
HttpOnly-сессию. Сервер принимает только loopback IP. Для свободного порта:
`--listen 127.0.0.1:0`. Второй процесс с той же базой отклоняется.

Полная карта действий TUI и Web: [USER_GUIDE.md](USER_GUIDE.md).

## Как пользоваться

1. Создайте или выберите проект, укажите область проверки.
2. В обзоре нажмите «Начать проверку»: область → профиль → подтверждение.
3. В «Задачах» смотрите этап, журнал и прогресс или остановите работу.
4. В «Хостах» откройте узел и сервис. В «Результатах» доступны доказательства
   и экспорт. API экспорта поддерживает `?format=json`, `csv`, `html`.
5. В «Доступах» добавьте учётку; параметры и разрешения находятся в настройках.

В TUI открытие проекта ведёт в обзор с тем же маршрутом запуска. Клавиша `0`
возвращает в обзор; существующая навигация и расширенные действия сохранены.

Web содержит обычные формы для основных сценариев. «Полный TUI в браузере»
открывает действующий терминальный интерфейс для проводников, консолей и
остальных расширенных действий. Нажмите на терминал для ввода; доступны
экранные стрелки и передача текста. Файлы этих действий сохраняются на машине
сервера, как в обычном TUI. Это ещё не отдельные нативные веб-проводники.

## Общие задачи и ограничения

Discovery, проверки, AD и веб-модули используют общий сервис. Задачи видны
обоим интерфейсам; отмена работает независимо от источника запуска. Закрытие
вкладки оставляет задачи активными. Завершение процесса останавливает работу.
Снимки и журнал сохраняются в SQLite; после аварии незавершённая задача
показывается как прерванная и сама повторно не запускается.

AD-профиль использует найденные LDAP/DNS-сведения, без фиксированных имён GOAD.
Новые DNS-адреса не расширяют выбранную область. Полный план дальнейшей
автоматизации: [AUTOMATION_UI_WEB_PLAN.md](AUTOMATION_UI_WEB_PLAN.md).

Проверки выполнялись только локально: тесты Go и браузер с временной базой и
HTTP-сервисом на loopback. Реальный AD-стенд в этом этапе не сканировался.

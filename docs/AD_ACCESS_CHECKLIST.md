# AD: учётные записи и возможные пути первоначального доступа

Срез реализации на 2026-10-13. Проверен код и установленный каталог;
сетевые проверки в рамках этого аудита не запускались. «Есть» означает
наличие реализации, а не подтверждённое выполнение в конкретном домене.
Все новые проверки должны выполняться собственным движком без запуска nxc,
Nuclei, Nmap или Metasploit.

| Проверка | Сейчас | Что требуется |
| --- | --- | --- |
| Поиск DC, домена, LDAP/Kerberos/DNS SRV | Есть в AD Scan | Сохранить как этап инвентаризации |
| Имена пользователей через anonymous LDAP | Есть в AD Scan; ограниченный каталог, только если сервер разрешает чтение | Отказ и неполный результат отображаются отдельно |
| LDAP с доменной учёткой или NTLM-хешем | Есть отдельный аудит в проекте с выбором сохранённой учётки | Доступ к атрибутам зависит от прав учётки |
| SMB null/guest, список шар | Есть в AD Scan и SMB-проводнике | Отдельно показывать факт входа и доступ к каждой шаре |
| Проверка известного пароля/NTLM-хеша | Есть SMB/LDAP-клиенты и механизм проверки credentials | Не смешивать с перебором и обходом всех учёток |
| Поиск секретов в файлах SMB | Есть ограниченный поиск конфигураций, значения маскируются | SYSVOL/NETLOGON отдельно обнаруживает устаревший GPP cpassword; пароли не извлекаются |
| AS-REP roasting | Native AS-REQ без пароля по собранным/указанным именам; RC4/AES → Hashcat, результаты проекта | Ключ сессии не расшифровывается, пригодный для входа TGT/ccache не создаётся; [параметры и ограничения](AD_RECON.md#as-rep-без-пароля) |
| Kerberoasting | LDAP-кандидаты SPN | TGS/hash extraction не поддерживается; SPN не доказывает слабый пароль |
| Kerberos user enumeration | AS-REP проверяет собранные/указанные имена, различает pre-auth, неизвестное имя и отказ KDC | Словарь имён автоматически не перебирается |
| pre2k | Кандидаты по LDAP-флагам компьютера, без попытки входа | Предсказуемый пароль/TGT не проверяется |
| Coercion: PetitPotam, DFSCoerce, PrinterBug, ShadowCoerce, MSEven | Реализованы 5 named-pipe вариантов и локальный SMB-приёмник | [Методы, порты и ограничения](COERCION.md); на Windows ещё не проверено |
| SMB signing required | Есть чтение SecurityMode и шаблон smb-signing | Объединить результаты в AD-аудите; отсутствие подписи не доказывает успешный relay |
| LDAP signing / channel binding | NTLM bind к LDAP/LDAPS отдельным действием; результат отражает принятие выбранной учётки, не полную серверную политику | relay не выполняется |
| AD CS | LDAP-аудит CA, шаблонов и ограниченных ESC-кандидатов; эффективные ACL не рассчитываются полностью | Не полный аудит ESC; наличие /certsrv не доказывает ESC8 |
| Парольная политика / Fine-Grained Password Policies | Читаются доменная политика и PSO в LDAP-аудите | Password spray не поддерживается |
| Password spray | Не поддерживается | Пароли по списку учёток не проверяются |
| LAPS / Windows LAPS, gMSA | LDAP-аудит сообщает, доступны ли текущей учётке секретные атрибуты; значения редактируются | Экспорт и хеширование значений не поддерживаются |
| Делегирование / ACL / trusts | LDAP показывает constrained delegation, RBCD-атрибут, trusts и ограниченные ACL-кандидаты | Полная модель эффективных прав и путей атаки отсутствует |
| Zerologon | Есть CheckZerologon и шаблон CVE-2020-1472 | Активная проверка отдельно; пароль машины код не меняет, сетевое выполнение здесь не проверялось |

## Порядок расширения

1. Read-only каталог LDAP, парольные политики, компьютеры, SYSVOL/GPP и AD CS конфигурация доступны в отдельном действии проекта.
2. AS-REP сохраняет зашифрованный ответ KDC для офлайн-проверки пароля. Перебор паролей, TGS extraction, экспорт LAPS/gMSA и relay не входят в этот этап. Coerce запускается отдельным явным действием с локальным приёмником.

В интерфейсе различать: «не проверено», «кандидат», «подтверждено»,
«нет прав», «ошибка», «неполный результат». Пустой список после отказа LDAP
не должен означать, что уязвимых учёток нет.

## Основания

- `internal/adscan/scanner.go`: RootDSE, anonymousLDAPUsers, DNS SRV, AD CS пути.
- `internal/tui/ad_scan.go`: сохранение кандидатов и SMB null/guest пробы.
- `internal/engine/js/ldap.go`, `ldap_adenum.go`: LDAP-клиент и GetAD* методы.
- `internal/engine/js/smb.go`, `smb_readonly.go`: вход, signing, чтение конфигураций.
- `internal/engine/js/dcerpc_zerologon.go`: активная проверка Zerologon.
- [NetExec pre2k](https://github.com/Pennyw0rth/NetExec/blob/main/nxc/modules/pre2k.py): специализированный поиск компьютеров и отдельные попытки получить TGT.
- [NetExec coerce_plus](https://github.com/Pennyw0rth/NetExec/blob/main/nxc/modules/coerce_plus.py): методы coercion и разделение подключения/вызова.

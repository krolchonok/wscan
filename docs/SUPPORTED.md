# Возможности wscan

Проверки выполняются нашим Go/JavaScript/Lua-движком. Внешние Nuclei,
Nmap и Metasploit не используются. Обычные утилиты и интерпретаторы разрешены.
WinPEAS — согласованное исключение, только ручной запуск с AllowExploit.

## Поддерживается

| Возможность | Реализация и границы |
| --- | --- |
| Проекты, цели, история, находки, задачи | TUI, SQLite, отмена, ограничения скорости и параллельности |
| Экспорт | JSON, HTML, CSV |
| TCP discovery | Connect scan, общие/Top-N/пользовательские порты, диапазон 1–65535 |
| UDP discovery | Пробы; открытым считается только ответивший порт |
| Сервисы и версии | Вся установленная база match/softmatch из nmap-service-probes; собственные TCP/UDP-пробы, fallback, TLS и извлечение продукта/версии |
| CIDR, живые хосты и имена | ICMP с fallback ping, DNS/PTR, выбор сетевых интерфейсов |
| AD-аудит | LDAP/DNS SRV, SMB/RDP-метаданные, предварительные признаки конфигурации и AD CS |
| HTTP/HTTPS | method/path/raw, заголовки, body, variables, payloads |
| HTTP-сессии | cookie-reuse; disable-cookie; cookies изолированы по шаблону и цели |
| HTTP-редиректы | redirects/host-redirects, max-redirects; только тот же хост и выбранный порт; по умолчанию выключены |
| HTTP-ограничения | stop-at-first-match, max-size (по умолчанию 1 МиБ), disable-path-automerge |
| Матчеры | status, word, regex, binary, DSL, size, XPath; комбинации и отрицания |
| Экстракторы | regex, kval, DSL, JSON (ограниченный jq), XPath |
| Payloads | Inline/файловые; batteringram, pitchfork, clusterbomb с лимитом комбинаций |
| TCP/network, DNS, TLS | Собственные исполнители; сертификаты и реализованные параметры TLS |
| Workflows и flow | Поддержанные сценарии через собственный исполнитель и встроенный goja |
| JavaScript | Встроенный goja, init/pre-condition, аргументы, exports и реализованные API |
| JS-модули | net, bytes, ssh, redis, mysql, postgres, smb, mssql, fs, vnc, rdp, ldap — реализованный поднабор API, не весь SDK Nuclei |
| NSE | Встроенный gopher-lua, наши сетевые модули и совместимые nselib; проверка импорта не гарантирует поддержку каждого action |
| SMB | Browse, чтение файлов/шар и ограниченный поиск конфигураций |
| FTP/FTPS | Browse, предпросмотр, скачивание, экспорт; проверка TLS |
| MySQL/PostgreSQL/MSSQL | Подключение и реализованные действия чтения/аудита; команды отдельно разрешаются |
| WinRM | Подключение, реализованные файловые действия и PowerShell на целевой ОС |
| credentials | Хранение, поддержанные проверки входа/перебор с ограничениями попыток |
| Web Discovery | Поиск путей, расширений и vhosts, фильтры ответов и wildcard, собственные HTTP-запросы |
| SQLi в формах | Реализованные проверки ошибок/сравнений/задержек; не весь набор SQLmap, отдельно AllowExploit |
| Web LFI | Ограниченные пробы одного URL/query-параметра, отдельно AllowExploit |
| File upload | Проверка формы/загрузки и исполнения маркера; не автоматическая установка веб-шелла |
| Kyocera | GET/WSDL-проверка интерфейса и отдельное реализованное действие экспорта адресной книги |
| code: | Python/Ruby/bash и другие найденные интерпретаторы; отдельно AllowCodeExec; запрещённые внешние сканеры не являются допустимой обёрткой |
| MSSQL передача файла | Python HTTP-сервер одного файла, контроль SHA-256, отдельное разрешение |
| WinPEAS | Готовый инструмент из комплекта; ручной запуск на Windows через MSSQL |

## Ограничено или не поддерживается

| Возможность | Статус |
| --- | --- |
| Полная совместимость с Nuclei/Nmap | Не заявляется; внешнего fallback нет |
| JS oracle/rsync/smtp | Не реализованы; require() отклоняется, каталог показывает причину |
| Неизвестные JS-модули / динамический require() | Отклоняются офлайн; отсутствие статически найденной проблемы не гарантирует выполнение всех методов |
| headless, websocket, whois | Не поддерживаются |
| file, локальные/self-contained аудиты | Не выбираются для проверок удалённых хостов |
| HTTP pre-condition, global-matchers | Не реализованы; непустые/включённые настройки отклоняются |
| HTTP digest-username/digest-password | Не реализованы; непустые значения отклоняются |
| HTTP req-condition, iterate-all, read-all | Не реализованы; включённые настройки отклоняются |
| HTTP редирект на другой хост/порт | Не выполняется: сохраняется выбранная область |
| Полный raw unsafe/fuzzing/headless SDK | Не поддерживается; raw — обработка реализованных HTTP-форм, не произвольный транспорт |
| Полный jq и все DSL-функции | Только реализованный набор |
| OAST / interactsh | Собственный HTTP-callback; не полный DNS/SMTP/HTTP сервис Interactsh; доступность callback должна быть настроена |
| UDP без ответа | Нельзя отличить open/filtered; отсутствие результата не означает закрытый порт |
| Полный Nmap NSE API | Не все модули, корутины и методы реализованы; несовместимые импорты/ошибки показываются |
| Kerberoasting/AS-REP находки AD-аудита | Предварительные LDAP-признаки, не автоматическое получение/взлом хешей |
| p0wny-shell | Справочный сторонний файл, не включён в релиз и не запускается движком |
| Windows/macOS release | Текущий готовый архив только Linux x86-64; переносимость исходников не равна проверенной сборке для другой ОС |

## Как получить список

`wscan capabilities` выводит эту таблицу без открытия базы или сетевых запросов.
`wscan audit-library OUTPUT_DIR` проверяет установленную библиотеку офлайн и
создаёт README.md, summary.json и compatibility.json с причинами недоступности.

В summary.json `native_compatible` означает допуск по офлайн-проверке,
а `target_executions_verified` всегда равен 0: каталог ничего не сканирует.
Реальное выполнение требует выбранной цели, доступов, разрешений и проверки
ошибок задачи. Нет находок — не доказательство отсутствия уязвимостей.
Покрытие каталога зависит от версии библиотеки и доступных интерпретаторов.

Семантика HTTP-полей сверена с описанием исходного формата:
[описание HTTP-полей](https://github.com/projectdiscovery/nuclei/blob/dev/SYNTAX-REFERENCE.md).

## Сигнатуры сервисов

Начиная с v0.1.4 движок загружает все match/softmatch из установленного
`library/nmap/nmap-service-probes`. Текущий снимок: 12 171 сигнатура, 187 проб,
ошибок загрузки 0. Проверка загрузки: `wscan signatures` (без сетевых запросов).
Обновление базы: `wscan library update`.

Поддерживаются бинарные ответы, флаги i/s, capture-группы, lookaround,
backreference, fallback, p/v/i/h/o/d/cpe, $P/$I/$SUBST. Дополнительные сведения
сохраняются вместе с сервисом и доступны в JSON-экспорте. Ошибки загрузки
указываются с номерами строк; ошибки или таймауты сопоставления не дают совпадения.

Включите «Определять версии сервисов» в настройках поиска портов. Это добавляет
активные протокольные пробы. Дополнительный этап использует до 8 проб, не более
6 секунд на сервис, до 1 секунды на одну пробу и до 64 КиБ ответа; соблюдает
общую частоту discovery и отмену. Выбираются пробы rarity <= 7 либо привязанные
к выбранному порту. Для уже распознанного HTTP используются HTTP-пробы и NULL.
Порты Exclude (в текущей базе TCP 9100–9107) исключаются из дополнительного этапа.
Номер версии остаётся пустым, если сигнатура определила только продукт.

Это не полная реализация алгоритма nmap -sV: лимиты могут исключить нужную пробу;
нет RPC grinder, tcpwrapped-эвристики и сканирования UDP open|filtered.
Полная загрузка правил не означает проверку каждого продукта на реальном устройстве.
Формат данных: https://nmap.org/book/vscan-fileformat.html.

## Критичность результатов

В списках результатов и карточке находки критичность выделена цветом:
critical — красный, high — оранжевый, medium — жёлтый, low — зелёный,
info — синий, unknown — серый. Текстовые уровни и отметка выбора сохраняются.

Предупреждение `WARNING: Server does not require authentication` из
`vnc-info` классифицируется как critical в TUI, CLI и экспортах. Обычный
результат версии/способов защиты VNC остаётся info. При чтении старых
находок уровень также исправляется по сохранённому предупреждению;
пересканирование не требуется, исторические доказательства не изменяются.
Скрипт устанавливает наличие предлагаемого способа доступа без авторизации,
но не подтверждает получение рабочего стола или возможность управления.

## Общие HTTP-ответы между шаблонами

Внутри одного Scan/ScanProgress одинаковые обычные GET/HEAD разных шаблонов
используют общий снимок ответа. Параллельные запросы объединяются: один
отправляется в сеть, остальные ждут его результат с поддержкой отмены.
Матчеры, extractors, переменные и находки каждого шаблона выполняются отдельно.
Время находки соответствует исходному запросу. Новый запуск получает новый кеш.

Ключ учитывает метод, полный URL/порт, Host, все подготовленные заголовки
(включая Authorization), настройки редиректов, таймаут и лимит тела.
Cookie-запросы, raw, flow/workflow, несколько HTTP-блоков, payload-наборы,
проверки времени, OAST, явный SNI, URL с query и активные классы атак
не используют общие ответы. Повторный запрос того же шаблона остаётся свежим.
Действия вне этого режима сбрасывают кеш хоста и блокируют его наполнение
до завершения; устаревшие параллельные ответы не возвращаются в кеш.

Ошибки, ответы вне 2xx, Set-Cookie (также в цепочке редиректов),
Cache-Control no-store/no-cache/private/max-age=0/s-maxage=0, Vary:* и
ответы более 1 МиБ и усечённые тела не сохраняются. Лимит кеша — 64 МиБ и 1024 записи;
он хранится только в RAM и удаляется по завершении запуска.
Это снимок данных для проверок одного запуска, а не постоянный браузерный кеш.

Журнал задачи показывает число сэкономленных HTTP-запросов; CLI возвращает
`http_requests_saved`. Это число объединённых обращений к ответу, а не
число предотвращённых отдельных переходов в цепочке редиректов.

## Офлайн-сверка сохранённых версий с CVE

Меню «4 Взаимодействие» → «CVE — сверить сохранённые версии» обрабатывает
все сохранённые сервисы текущего проекта. Действие читает локальный
`products.json`, не запускает сканер, шаблоны или внешние программы,
не подключается к целям и не скачивает базу. Отсутствующая локальная база — ошибка.

Сопоставление использует сохранённый продукт/точный псевдоним или CPE;
порт и имя протокола не доказывают продукт. Версия CPE ОС не заменяется версией
приложения. Противоречивые, неполные, beta/rc и неизвестные версии явно
отмечаются как неоценённые. Диапазоны сравниваются численно: условия внутри
группы соединены «и», группы — «или»; дубликаты CVE для одного продукта
и сервиса объединяются.

В текущей проверенной библиотеке доступны 60 формальных правил диапазонов:
38 для GitLab и 22 для MikroTik RouterOS. Остальные веб/NSE-шаблоны не являются
автоматически пригодной базой диапазонов. Новые формальные правила из библиотеки
подхватываются при следующей локальной сверке. Это не полная и не автоматически
обновляемая база всех CVE. Для каждого сервиса отображаются совпадения либо причина
неоценённости/отсутствия покрытия; отсутствие совпадений не означает безопасность.

Результаты сохраняются в историю проекта и доступны в обычных деталях/экспорте.
Совпадения имеют исходную критичность CVE и пометку «потенциально по версии»:
доступность компонента, условия эксплуатации и backport исправлений не проверяются.
Доказательства содержат исходную версию, диапазоны, условия из локальной базы и её SHA-256.

## Активные NSE vuln-проверки проекта

Отдельный пункт «4 Взаимодействие» → «NSE --script vuln — активные проверки»
выбирает точную категорию `vuln` из локального NSE-каталога. Это отдельное действие
от офлайн-сверки CVE. Запускается наш Lua/NSE-движок, внешний Nmap не вызывается.
Используются сохранённые сервисы всех хостов проекта: поиск хостов, портов и
повторное определение версий не запускаются. Портовые/хостовые правила каждого
скрипта определяют применимость; сохранённые product/version передаются движку.

Запуск отправляет сетевые запросы к целям. DoS-скрипты исключены всегда;
`exploit`/`intrusive` и скрипты сильного воздействия учитывают настройку проекта
`AllowExploit`. Несовместимые и отсутствующие скрипты пропускаются с причиной
в журнале задания. Категория `vuln` не означает отсутствие побочных эффектов
и не является гарантией обнаружения всех CVE. Локальная проверка совместимости
проверяет загрузку/импорты; ошибки исполнения отображаются отдельно.
Результаты сохраняются в историю проекта. Новые/необнаруженные адреса подсети
такой запуск не охватывает.

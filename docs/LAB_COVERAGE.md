# Покрытие Windows / AD и локальных учёток

Изменения по проверке лаборатории 10.0.5.0/24, 2026-10-13. Текущие исходники находятся в `sources`; собранный исполняемый файл в рабочем каталоге — `../wscan`.

## Локальная проверка credentials

При открытии SMB credential-проверки локальный режим включён по умолчанию. `l` переключает локальную область и область сохранённой учётки; переключение видно в форме перед запуском. Для доменной проверки нужно выбрать соответствующий режим явно.

Локальный режим:

- Получает имя машины из NTLM challenge без передачи пароля.
- Читает роль через DSROLE. При отказе может распознать клиентскую редакцию Windows через встроенный `smb-os-discovery`; свежий Windows-аудит локальной SAM тоже служит источником роли. Сам по себе NTLM target `LAB` не означает DC: такой ответ дают и доменные клиенты.
- Исключает роли DC 4/5, подтверждённый LDAP AD DS и неизвестную роль. Подставляет имя машины в NTLM domain; UPN, `DOMAIN\user` и посторонняя доменная область отклоняются. Доменного fallback нет.
- Учитывает неудачи по машине и имени локального пользователя, отдельно от доменных попыток. Останавливает аккаунт после успеха, ответа о блокировке или лимита ошибок. Пароли в журнал попыток не попадают.
- Сохраняет действующее ограничение проекта; прочитанный локальный порог уменьшает бюджет до `threshold - 1`. При threshold=1 попытки не отправляются. Порог 0 не отменяет ограничения приложения.

Локальная политика, прочитанная Windows-аудитом в текущем процессе, кэшируется на 15 минут отдельно для проекта/хоста. В CLI можно передать свежий отчёт с `--policy-report`. Доменная политика/PSO в качестве локальной не принимается. Неудачи от других программ приложению неизвестны, поэтому отсутствие локальных блокировок не гарантируется. Имена/адреса одного хоста следует использовать последовательно: журнал привязан к заданному адресу машины.

Для словаря работает потоковый CLI: до 5000 локальных имён, пароли читаются по строке, после успеха/лимита аккаунт исключается. По умолчанию 1 попытка/с и 3 ошибки за стандартное окно проекта. Повторный запуск с той же SQLite использует тот же журнал и проект.

```sh
./wscan local-smb --targets 10.0.5.20,10.0.5.21 \
  --users ./local-users.txt --passwords ./passwords.txt \
  --db ./local-audit.db --output ./local-result.json
```

Для одной пары: `--username Administrator`, пароль — из `WSCAN_AUDIT_PASSWORD`. Для применения политики добавьте `--policy-report ./windows-result.json`. Файл результата создаётся новым с правами 0600; существующий не перезаписывается. Прямые SMB default-login/NSE brute-шаблоны используют собственные настройки и не получают ограничение local-only автоматически: для локальных Windows-учёток используйте этот отдельный режим.

## Данные после валидного входа

В «Проверки AD» добавлена отдельная `passpolicy`. Общий directory-аудит также сохраняет нормализованные `password_policies`:

- длина, история, сложность, обратимое хранение;
- минимальный и максимальный возраст, в секундах;
- порог, длительность и окно блокировки;
- PSO: precedence, applies-to; пользователи сохраняют `msDS-ResultantPSO`.

Отсутствующий атрибут сохраняется как неизвестный, а не 0/false; повреждённые значения и неполные ответы видны отдельно. Нулевой максимальный возраст означает отсутствие срока. Нет полного расчёта эффективных PSO через все вложенные группы; `msDS-ResultantPSO` является отдельным серверным фактом.

Post-auth LDAP-модуль `ldap-passpolicy` доступен после валидной учётки. Остальные LDAP-модули читают defaultNamingContext, поэтому короткое NTLM-имя `LAB` не превращается в ошибочный BaseDN `DC=LAB`. Credential-проверки и post-auth bind выполняют одну NTLM-аутентификацию без повторного simple bind. Отказы запросов после успешного bind не учитываются как неверный пароль.

```sh
./wscan audit --mode passpolicy --host 10.0.5.10 --domain lab.local \
  --credential-domain LAB --username Administrator --port 389 \
  --output ./passpolicy.json
```

Пароль задаётся через `WSCAN_AUDIT_PASSWORD`, NTLM-хеш — через `WSCAN_AUDIT_NTHASH`; секрет не передаётся как CLI-аргумент и не включается в JSON отчёта.

## Windows, сеть и DNS

`windows-audit` доступен в post-auth WinRM-модулях и в «Проверки AD». Один ограниченный запрос читает ОС, DomainRole/PartOfDomain, WDigest, QFE, интерфейсы, IP/DNS/gateway, маршруты, профили Windows Firewall и параметры DNS-зон. Ошибки разделов сохраняются независимо. Локальные параметры длины/истории/возраста/блокировки читаются NetUserModalsGet; сложность и обратимое хранение локальной SAM этим API не возвращаются и остаются неизвестными.

```sh
./wscan audit --mode windows --host 10.0.5.21 \
  --credential-domain CLIENT2 --username Administrator --port 5985 \
  --output ./windows-result.json
```

WinRM поддерживает 5985/5986. В форме `l` меняет транспорт; для LDAP-аудита `l` переключает 389/636. Windows collector требует PowerShell 3+ для JSON; на лабораторном Server 2008 R2 проверена версия 5.1. Длинный сценарий по возможности сжимается и передаётся в командной строке до 8000 символов; большие несжимаемые сценарии используют stdin, который может зависнуть на некоторых WinRS/PowerShell сочетаниях до таймаута. Дамп процессов, экспорт SAM/LSASS и изменение настроек отсутствуют. Add-Type компилирует небольшой reader NetAPI для чтения политики; аудит требует запуска команд через выбранную учётку.

WDigest=1 — подтверждённая настройка риска; отсутствующее значение на старой ОС — кандидат. Это не доказательство наличия конкретного пароля в памяти. QFE — инвентаризация KB, не база применимости и замещения патчей. Сетевые MS17-010/BlueKeep остаются отдельными проверками. Ошибка NIC/domain join не выводится из одного имени интерфейса: отчёт даёт фактическую конфигурацию для сопоставления с ожидаемой.

`audit --mode dns --host 10.0.5.10 --domain lab.local` выполняет нативный TCP AXFR с пределами числа сообщений/записей и читает RA в ответе SOA. Полный AXFR подтверждается начальной и конечной SOA. Отказ, обрыв, таймаут и неверный ответ разделены. RA=1 показывает объявленную рекурсию этому клиенту; глобальный open resolver не утверждается. DNS-записи не изменяются. В адаптере NSE исправлены таблицы алиасов и несколько возвращаемых аргументов `stdnse.get_script_args`.

## Первичная разведка и покрытие

```sh
./wscan ad-scan --scope 10.0.5.0/24 --db ./ad-audit.db \
  --library ./library --output ./ad-result.json --timeout 5m
```

Обход использует штатный Worker. Дополнительно сохраняются NTLM identity с источником, сведения о чтении SMB-шар, ошибки null/guest, результат SAMR и DNS AXFR. Domain SAMR-имена с подтверждённого DC могут использоваться для существующего AS-REP этапа. LSA RID-перебор и `smb-brute` автоматически не запускаются.

JSON содержит `Coverage` по хостам: confirmed / observed / candidate / negative / denied / error / incomplete / disabled / skipped. Windows-проверки записывают положительный ответ, отрицательный probe, транспортную ошибку и запрет активной проверки раздельно. Матрица также сохраняется в findings, чтобы пережить перезапуск. Уже выполненные Windows/NSE-проверки сохраняются при последующей отмене. Отмена раннего discovery ещё не обеспечивает полную запись частичной инвентаризации.

AS-REP поддерживает LDAP/SAMR/ручные имена и native AS-REQ. Теперь доступен `audit --mode asrep`: `--users` через запятую, `--users-file` по строке; без списка имена читаются через LDAP, при явно выбранной учётке — с bind. Пароль выбранной учётки используется только для сбора имён; AS-REQ целевых пользователей остаются без pre-auth.

```sh
./wscan audit --mode asrep --host 10.0.5.10 --domain lab.local \
  --users luke_skywalker,han_solo --output ./asrep.json
./wscan audit --mode kerberoast --host 10.0.5.10 --domain lab.local \
  --credential-domain LAB --username Administrator --port 389 \
  --output ./kerberoast.json
```

Kerberoasting доступен в TUI («Проверки AD») и CLI/API: LDAP SPN → TGT выбранной password/NT-hash учётки → TGS → Hashcat RC4/AES. В TUI `c` выбирает учётку, `l` — LDAP порт, `s` — необязательный список SPN. CLI поддерживает `--spns`, `--spns-file`, `--tgs-etypes 18,17,23`, `--rps`, `--export-dir`. По умолчанию выбраны AES-first и 2 запроса/с, автоматический список исключает машинные/отключённые аккаунты и krbtgt. Явный SPN всё равно проверяется на уникального активного владельца в LDAP; машинный SPN разрешён явно, но получение его ciphertext не подтверждает слабый человеческий пароль.

Ответы TGT/TGS проверяются по principal/realm, nonce и целостности; AES salt владельца читается отдельным AS-REQ без пароля, а не угадывается. Нестандартные salts/iterations, которые нельзя выразить в выбранном формате Hashcat, дают ошибку экспорта. TGT и session keys не сохраняются. Хеши — новые файлы 0600 в каталоге `kerberos-artifacts` рядом с JSON или выбранном `--export-dir`; уже полученные хеши сохраняются при отмене. Положительный TGS означает возможность офлайн-проверки ciphertext, не найденный пароль. Ключи/пароли не печатаются. Все Kerberos TCP-запросы идут только в явно выбранный KDC; внешние referrals, автоматический renewal, повтор неверного пароля и cracking отсутствуют.

Cracking, relay, pivot и эксплуатация RCE не добавлены. Проверки с возможным повреждением служб сохраняют существующий AllowExploit; это отдельные действия. Форматы экспорта сверены с [Hashcat](https://hashcat.net/wiki/doku.php?id=example_hashes) и [AES TGS parser](https://github.com/hashcat/hashcat/blob/master/src/modules/module_19700.c).

Для OpenWrt доступен post-auth SSH-модуль `openwrt-audit`: release, UCI firewall, маршруты и доступные nftables/iptables правила. Вывод ограничен; отказ привилегий означает неполный сбор. Правила не изменяются, выход в Интернет и pivot не выполняются; наличие разрешающего правила не доказывает достижимость всех внешних адресов.

## Проверка и источники

Проверки: `go test ./...`, `go vet ./...` и выборочные тесты новых пакетов с `-race` прошли. Локальные тесты: DOM/PSO interval/boolean/unknown parsing; запрет доменного входа в local-only; разделение счётчиков машин и остановка после успеха/lockout; фрагментированные SMB-ответы без Type 3; AXFR complete/refused/partial; статусы Windows JSON; CLI/help и права файлов. WS-Man fixture проверяет передачу Windows collector и длинного сжатого сценария с кириллицей, но не исполняет PowerShell. Reader NetAPI отдельно скомпилирован .NET SDK и выполнен на DC. После исправления WinRM прошли тесты engine/js, engine, tui и adscan, выборочные тесты WinRM с `-race` и vet для engine/js и tui.

Живой повтор на `.20`/`.21` подтвердил NTLM identity, нативную MS17-010 на `.20`, отрицательный probe на `.21`, отказы SAMR и адресованные машинам контрольные local-only попытки по заведомо тестовому имени. После восстановления DC `.10` повторно прочитаны доменная политика и Windows collector, проверены AS-REQ для всех 21 пользователей и DNS AXFR. Передача collector через stdin зависла, сжатая команда выполнилась; JSON теперь формируется через ConvertTo-Json. Артефакты: `reports/lab-coverage-20261013/implementation` и `reports/kerberos-recheck-20261013-152522` в рабочем каталоге.

Семантика флагов/параметров сверена с [Microsoft NTLM](https://learn.microsoft.com/en-us/troubleshoot/windows-server/windows-security/ntlm-user-authentication), [DSROLE](https://learn.microsoft.com/en-us/windows/win32/api/dsrole/nf-dsrole-dsrolegetprimarydomaininformation), [PSO](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adfinegrainedpasswordpolicy), [WDigest](https://support.microsoft.com/en-us/security/microsoft-security-advisory-update-to-improve-credentials-protection-and-management-may-13-2014) и [DNS zones](https://learn.microsoft.com/en-us/windows/win32/dns/microsoftdns-zone).

## Kerberos: режимы без известного пароля

В проекте: `3 AD-разведка` → «Учётки, Kerberos, SYSVOL».

- **AS-REP:** «Пользователи (имена или @файл)» принимает логины через запятую
  или `@/путь/users.txt`. Файл содержит один логин на строку; пустые строки и
  комментарии `#` пропускаются. TUI допускает до 5000 имён и файл до 1 МиБ.
  Проверяются имена и наличие pre-auth; пароли для запросов не используются.
- **Kerberoasting:** `a` переключает пароль/NT-хеш, логин без pre-auth и файл
  TGT. `c` выбирает учётку первого режима, `u` задаёт логин второго, `t` —
  путь к `.kirbi` (незашифрованный KRB-CRED) или `.ccache` v3/v4 третьего.
  `s` принимает SPN через запятую либо `@/путь/spns.txt`, `e` выбирает
  автоматическое шифрование / только RC4 / только AES, `Enter` запускает.
- Режим без pre-auth выполняет AS-REQ сразу для сервисов. KDC должен разрешать
  запрос выбранной учётке без pre-auth. Режим TGT отправляет TGS-REQ с ключом
  импортированного билета. Оба режима используют явный список SPN без LDAP-входа;
  сохранённые пароль/NT-хеш к ним не добавляются.
- Для AES в этих режимах укажи владельца: `HTTP/server.lab.example|svc_http`.
  Соль получается отдельным запросом к KDC. Если владелец/соль неизвестны,
  ciphertext сохраняется в `kerberoast-pending-*.json` со статусом incomplete.
  RC4 экспортируется без имени владельца. Получение ciphertext не доказывает
  слабость пароля; офлайн-подбор выполняется отдельно.
- TGT должен принадлежать выбранному домену, содержать сеансовый ключ и действовать
  сейчас. Service/referral билеты, неоднозначные файлы и повреждённые структуры
  отклоняются. Системный кеш, импорт в ОС и автоматическое продление не используются.
  Экспорты TUI находятся в `exports/kerberoast/project-ID/` каталога настроек.

CLI: `audit --mode kerberoast --host DC --domain DOMAIN --nopreauth-user USER
--spns-file spns.txt` или тот же режим с `--tgt-file ticket.ccache`.
`--username`, `--nopreauth-user`, `--tgt-file` взаимоисключающие.
Для AS-REP словарь задаётся через `audit --mode asrep ... --users-file users.txt`.

Обмен без pre-auth соответствует [режиму Rubeus](https://github.com/GhostPack/Rubeus#kerberoast);
формат ccache — [спецификации MIT Kerberos](https://web.mit.edu/kerberos/krb5-latest/doc/formats/ccache_file_format.html).
Проверки используют локальный синтетический KDC, включая RC4/AES, отсутствие
pre-auth/password, отмену с сохранением результатов и проверку импортируемых файлов.

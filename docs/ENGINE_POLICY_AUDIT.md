# Аудит правила «только наш движок»

Проверено 2026-10-11: актуальные Go-исходники, места запуска процессов и их
вызывающие функции, встроенные Lua/JavaScript, скрипты сборки, CI и состав релиза.
Первичный аудит сравнивал рабочую копию ../internal и sources/internal.
Исправления v0.1.2 внесены в sources — актуальный репозиторий приложения.
Старые отдельные бинарники не являются доказательством соответствия текущим исходникам.
Это статическая проверка; проверки против сетевых целей не запускались.

## Согласованное правило

- Сканирование, обработка YAML/NSE и протокольные проверки выполняет наш движок.
- Запрещены внешние движки Nuclei, Nmap, Metasploit и аналогичные пентест-инструменты.
- Обычные утилиты и интерпретаторы (Git, ping, Python/Ruby/bash, команды ОС) разрешены.
- WinPEAS разрешён отдельно: готовый инструмент для ручной постэксплуатации,
  без переписывания с нуля. Обычный скан не должен запускать его автоматически.
- Сторонние Go-библиотеки, встроенные goja/gopher-lua и файлы шаблонов разрешены:
  они работают внутри нашего процесса и не являются внешними программами.

## Что реально исполняет проверки

| Часть | Реализация | Вывод |
| --- | --- | --- |
| HTTP, TCP/network, DNS, TLS, DSL, payloads и workflows | internal/engine/exec.go и protocols.go | Наш Go-движок, бинарник Nuclei не нужен |
| flow и javascript | goja и наши JS-модули | Встроенный движок, require("nuclei/...") — имя API совместимости |
| NSE | internal/nse/nse.go:99,113 | Встроенный gopher-lua и Go-модули; Nmap не вызывается |
| Ограничение Lua | internal/nse/nse.go:375 | os.execute, io.popen, package.loadlib отключены |
| Поиск портов, сервисов, PTR и AD-аудит | internal/discovery, internal/adscan | Собственные сетевые реализации |
| SMB, FTP/FTPS, MySQL/PostgreSQL/MSSQL, LDAP, WinRM | Go-клиенты и наши модули | Локальные внешние сканеры не нужны |
| Проекты, учётки, история, экспорт | SQLite и internal/report | Встроенное хранение; JSON/HTML/CSV |

Ни в одном месте запуска процессов приложения не найден вызов бинарника
Nuclei, Nmap или Metasploit. Упоминания `msf-*` в проверках обозначают библиотечные
идентификаторы: сами по себе они не означают запуск msfconsole.
Наличие в пакете бинарника Nuclei до исправления было ошибкой упаковки,
а прежние README/FUNCTIONS ошибочно описывали внешние движки и fallback.

Проверены также зависимости, импортирующие os/exec: gopher-lua, терминальные
библиотеки и modernc/libc. У Lua внешнее исполнение отключено; определение
цветов может вызывать tmux, а терминальный ExecProcess используется служебным
интерфейсом. Это не дополнительные движки Nuclei/Nmap/Metasploit.
В текущей библиотеке в двух code:-шаблонах-кандидатах вне локального scope
не найдено упоминаний известных внешних пентест-программ в source.
Это не гарантия для произвольных новых/пользовательских скриптов.

## Что исправлено в поставке

- Из упаковщика удалены требование, копирование и chmod bin/nuclei.
- Из CI удалено скачивание внешнего Nuclei.
- Из start.sh удалено ошибочное требование установить Nmap.
- Из cmd/payload/build_payloads.sh удалена необязательная генерация через msfvenom;
  скрипт собирает только наш Go-агент.
- В README, FUNCTIONS и TRANSFER исправлено описание собственного движка.
- Вместо копирования всех tools релиз содержит только согласованный WinPEAS.
  p0wny-shell не вызывается автоматически нашим приложением и в новый архив не входит.
- reference-tools/getKyoceraCreds — справочные сторонние исходники: ручные
  run_nuclei.sh/run_msf.sh запускают внешние инструменты. Они не подключены
  к приложению, не запускаются CI и не включаются в релиз; запуск этих обёрток
  не является работой нашего движка и противоречил бы правилу.

## Что оставить

Собственные Go-исполнители, встроенные JS/Lua, YAML/NSE и nselib, протокольные
Go-библиотеки, SQLite, Git/ping и интерпретаторы. WinPEAS оставить готовым,
с явным ручным действием и AllowExploit. Его переписывание сейчас не требуется.
Ручные команды через WinRM/MSSQL — отдельные действия оператора, не движок сканера.

## Исправлено и что остаётся

В v0.1.2 добавлена регрессионная проверка с фиктивными nuclei/nmap/msfconsole/
msfvenom в PATH: обычные HTTP/NSE-проверки их не вызывают. WinPEAS оставлен.
JS oracle/rsync/smtp больше не выдаются как рабочие заглушки: каталог и runtime
возвращают явную причину. Неизвестные/динамические импорты проверяются офлайн.

Добавлены исполнение redirects/host-redirects/max-redirects, cookie-reuse/
disable-cookie, stop-at-first-match, max-size и disable-path-automerge.
Редиректы не покидают выбранный хост/порт; cookies не переходят между шаблонами
и целями. Исправлена отмена контекста HTTP до чтения тела.

Неподдержанные HTTP pre-condition, global-matchers, digest authentication,
req-condition, iterate-all и read-all теперь отклоняются вместо молчаливого
игнорирования. Нулевые/выключенные настройки не блокируют шаблон.
Шесть сбоев тестовых адресов SSH/Redis/SMB устранены; полный набор тестов и
вет-проверка проходят. CI больше не публикует сборку при ошибках этих проверок.

Команда capabilities выводит SUPPORTED.md. Audit-library выдаёт summary.json
с отдельным target_executions_verified=0: совместимость не означает выполнение.
Оставшиеся ограничения и актуальный список — в [SUPPORTED.md](SUPPORTED.md).
Переписывать Python HTTP-сервер или WinPEAS для соблюдения правила не требуется.
Для p0wny-shell отдельное исключение не утверждено: он не входит в поставку.

headless, websocket и whois сейчас не поддерживаются. Локальные file/self-contained
проверки исключаются из выбора для удалённых хостов. Эти ограничения нельзя
компенсировать скрытым запуском Nuclei. Нужно развивать собственные возможности
или честно показывать недоступность; проценты в старых TODO/RELEASE_PLAN не
являются новым замером покрытия.

# wscan — план релизов движка (по частям)

Принцип: **только наш движок** (без `bin/nuclei`/`bin/nmap`), с одним явным исключением — `code:` (R11): реальный внешний интерпретатор на машине сканера, per-project opt-in с обязательным предупреждением в TUI.
Текущая совместимость nuclei-шаблонов: **79.58% (11198/14072)**.

## Разбор несовместимых

### Принципиально вне scope (не трогаем)
- [x] `code` — реализовано (R11), см. ниже. Ушло из вне-scope.
- [ ] `self-contained` ~1690 — запросы к **своим/внешним** эндпойнтам, не к цели.
- [ ] `file` / локальный аудит ОС ~630 — анализ **локальных файлов**, не сетевая проверка.
- [ ] `javascript` ~19 (first-reason) — нужен nuclei-уровня JS SDK (`nuclei/net`, `nuclei/http`, ...), не просто JS-движок; см. R10 и бэклог. `flow` ушло из этого списка — сделано в R10 на встроенном JS без SDK.
- [ ] `unsafe` ~57 — rawhttp с намеренно битыми байтами (обход HTTP-стека).
- [ ] `fuzzing` — DAST-фаззинг (отдельный большой режим); `pre-condition` без fuzzing почти не встречается.
- [ ] `headless` ~222 — нужен браузер (DOM XSS / waitdialog / JS); критичные CVE уже есть в HTTP. Не делаем.

### Можно добить нашим движком — релизим по частям
- [x] **R1. Безвредные поля** (`max-size`, `read-all`, digest/cookie) — игнорируются. (+25)
- [x] **R2. JSON-экстрактор** (мини-jq: `.a.b`, `.arr[]`, `.field?`, `select(...)`) по телу ответа. (+92)
- [x] **R3. Крайние случаи матчеров** — матчеры требуются на уровне шаблона, а не каждого запроса (мульти-шаговые req-condition). (+45)
- [x] **R4. Workflows** — оркестрация: referenced-шаблон грузится из каталога и исполняется; при совпадении запускаются subtemplates (рекурсивно, лимит глубины). Tag-based entries пропускаются. (+207)
- [x] **R5. Extractor-only** — шаблоны без matchers, только с extractors (токены/tech): находка при успешном non-internal extractor. (~+202)
- [x] **R6. XPath + мелкие HTTP-поля** — matcher/extractor `xpath` (+ attribute); игнор `pre-condition`/`global-matchers`/`id`/`disable-path-automerge`. (+15 совместимости; DAST+fuzzing по-прежнему вне scope)
- [x] **R7. DSL crypto/gadgets** — `hmac`, `aes_cbc`, `aes_gcm`, `rand_ip`, `generate_java_gadget` (URLDNS), `jarm(host)`. В основном runtime, не % каталога.
- [x] **R8. SSL version/cipher** — `min_version`/`max_version`, env `tls_version`/`cipher`; dsl-экстрактор `tls_version, cipher`.
- [x] **R9. Парсер** — `tcp`/`network` `port` как список, `info.reference` как скаляр. (+16, но убрало все 17 настоящих parse-ошибок в каталоге)
- [x] **R10. `flow`** — встроенный JS (goja, без внешнего процесса): скрипт вызывает `http(N)`/`tcp(N)`/`network(N)`/`dns(N)`/`ssl(N)`, которые делегируют в уже существующие исполнители; `template[...]`/`set()` для переменных между шагами. `code`/`javascript` по-прежнему недоступны и ловятся на парсинге, а не в середине скана. (+1075; 99.3% смоук-подтверждены реально исполняемыми)
- [x] **R11. `code:`** — единственное сознательное исключение из «только наш движок», по явному решению владельца проекта. Реальный `python3`/`ruby`/`bash`/... на машине сканера (не песочница): исходник в temp-файл + таймаут + на unix отдельная process group с `SIGKILL` всей группы по таймауту (иначе потомок вроде `sleep` в shell-скрипте держит pipe и блокирует `Cmd.Wait()` дольше таймаута) + `WaitDelay`-бэкстоп. Доступность в каталоге — по факту наличия интерпретатора (`exec.LookPath`), не заглушка. Выполнение отдельно гейтится per-project флагом `AllowCodeExec` (по умолчанию `false`), включение только через экран-предупреждение в TUI. Заодно: `brute.delay`/`brute.threads` для NSE brute-скриптов теперь выводятся из RPS/параллельности скана, а не из дефолтов nmap. (34 `code:`-шаблона в библиотеке, 33 совместимы на этой машине — 1 требует `ruby`, которого тут нет)

## Правила релиза каждой части
1. Реализация изолированно, с юнит/интеграционным тестом.
2. `go build ./...` + `go vet` + тесты зелёные (кроме известного layout-теста TUI).
3. Пересобрать `wscan`, замерить прирост совместимости.
4. Отметить часть здесь и в `TODO.md`.

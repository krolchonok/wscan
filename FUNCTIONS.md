# Возможности и устройство wscan

Этот документ фиксирует назначение, пользовательские функции и текущий поток работы `wscan`. Он описывает именно реализованный прототип и его границы.

## Назначение

`wscan` — модульный мультитул для управления проектами проверки, обнаружения TCP-сервисов, определения их типа и версии, запуска совместимых HTTP-шаблонов Nuclei и сохранения результатов в локальную базу с выгрузкой отчетов. Сканер написан на Go, использует встроенный TCP connect scanner и не требует установки Nmap или RustScan.

## Основные пользовательские функции

- **Проекты:** создавать отдельные рабочие наборы с целями, лимитами и выбранными шаблонами.
- **Цели:** добавлять IP-адреса и домены; HTTP/HTTPS URL можно указывать напрямую.
- **Обнаружение портов (TCP/UDP) с параметрами:** действие Discover открывает экран параметров — набор портов (Common / Top 100 / Top 1000 / Все 1–65535 / свой список), TCP и/или UDP, определять ли версии. Top-N портов берётся из `library/nmap/nmap-services` по частоте открытости (аналог `nmap --top-ports`); свой список принимает перечисления и диапазоны (`22,80,443,8000-8100`). Полный TCP диапазон (1–65535) выбирается в параметрах discovery. UDP — best-effort (см. «границы»).
- **Определение сервиса и версии (`-sV`-подобный режим):** проверять найденные открытые TCP-порты ограниченными протокольными пробами. Сканер использует приветственные баннеры, HTTP `HEAD` и Redis `PING`; извлечённые имя сервиса, продукт и версия сохраняются вместе с портом. Для TLS-портов выполняется handshake, проверка доверия сертификату для этой идентификации не является целью.
- **Nuclei-шаблоны:** выбранные шаблоны исполняются полным Nuclei, включая HTTP, raw, flow, payloads, pre-condition/fuzzing, DNS/TCP/TLS, JavaScript и headless. При отсутствии Nuclei остаётся ограниченный собственный HTTP-движок с конкретными причинами несовместимости.
- **Ограничение нагрузки:** задавать скорость и параллельность отдельно для обнаружения портов и HTTP-проверок; задавать timeout и retries для HTTP-движка.
- **Выбор проверок:** выполняются выбранные пользователем совместимые шаблоны и скрипты; категории и отдельные проверки отмечаются вручную.
- **История:** сохранять запуски, статус, время, открытые сервисы и находки в SQLite.
- **Отчёты:** экспортировать один запуск в JSON, HTML или CSV.
- **TUI и CLI:** интерактивно вести проекты или автоматизировать scan/export командами.
- **Платформы:** Go-код рассчитан на Linux и Windows; бинарник собирается отдельно под целевую ОС.

## Поток одного запуска

1. CLI/TUI загружает проект, цели, лимиты и выбранные шаблоны.
2. Каталог загружает шаблон из локального кэша; при отсутствии кэша использует каталог Nuclei.
3. Каталог проверяет загрузку полными движками. Оригинальный YAML передаётся Nuclei целиком; родной парсер используется для окружения без Nuclei.
4. Если discovery включён, цель разрешается в IP, затем TCP connect проверяет выбранный набор портов с заданными RPS и параллельностью.
5. На открытом порту выполняется ограниченное определение сервиса/версии. Веб-сервисы превращаются в URL для HTTP-проверок; явно заданные HTTP URL также сохраняются как цели.
6. Полные движки исполняют выбранные проверки: Nuclei применяет HTTP RPS/concurrency/timeout/retry; Nmap получает список портов и script-timeout. Результаты сохраняются в общий запуск.
7. Завершённый запуск и его результаты доступны в истории и экспорте.

Если discovery выключен, сканер пропускает TCP-поиск и использует только явно указанные HTTP(S) цели.

## Управление

Запуск TUI:

```sh
go run .
```

Список проектов: `↑/↓` выделение, `Enter` открыть, `n` создать проект, `q`/`Esc` выход.

Открытый проект — рабочий стол в три колонки (Miller columns), накапливающий результаты всех запусков проекта, а не только последнего:

- **Хосты** (первая колонка) — каждый добавленный хост плюс строка «Все хосты» для действий на весь проект. Показывает число портов и находок на хост.
- **Порты/сервисы** (вторая колонка) — сервисы, обнаруженные на выбранном хосте, с именем, продуктом и версией.
- **Детали и находки** (третья колонка) — протокол/продукт/версия выбранного порта и находки на нём.

`Tab`/`Shift+Tab` переключают колонку, `↑/↓` двигают выбор внутри неё.

Действия запускаются клавишей `Enter` и выполняются в фоне (не блокируют интерфейс):

- на хосте или «Все хосты»: Discover ports & versions, Nuclei проверки, Nmap NSE скрипты, Полный скан (discovery + библиотека проекта);
- на конкретном порту (колонка «Порты» или «Детали», выбран сервис): сразу выбор проверок именно для этого порта.

Nuclei/NSE-действия используют известные сервисы. Nmap повторно проверяет состояние только явно перечисленных портов перед NSE, новый диапазон не добавляется.

Прочие клавиши на столе: `a` — добавить хост, `d` — удалить выбранный хост, `r` — исправить хост с повреждённой кодировкой, `g` — задачи всех проектов (этап, процент и счётчик прогресса, время, отмена `x`, `Enter` — подробности и журнал задачи, затем `Enter` — открыть проект и результат), `t` — библиотека проверок проекта (набор по умолчанию для «Полный скан»), `p` — настройки сканирования, `h` — история запусков, `e` — экспорт последнего запуска, `Esc` — назад к списку проектов, `?` — справка по клавишам.

В меню категорий: `Space` — выбрать/снять **всю категорию целиком** (чекбокс `[✓]` полностью, `[~]` частично, `[ ]` пусто), `A` — отметить все видимые категории, `x` — снять, `Enter` — зайти в категорию к отдельным проверкам, `1`/`2`/`3` — как группировать (по типу / по продукту / по сервису); по умолчанию — сервисы, `/` — поиск по имени категории.

В списке отдельных проверок категории: `↑/↓` выбор, `Space`/`Enter` — отметить проверку, `A` — выбрать всю видимую группу, `x` — снять выбор, `/` — поиск по пути/тегам, `End` — перейти на строку запуска, `Enter` — открыть сводку, затем `Enter` — запустить, `Esc` — назад к категориям.

Запуск использует выбранные вручную проверки и параметры портов.

CLI:

```sh
wscan scan PROJECT_ID
wscan export PROJECT_ID RUN_ID json|html|csv OUTPUT_PATH
```

## Данные и модули

- `internal/domain` — модели проектов, сервисов, шаблонов, запусков и находок.
- `internal/storage` — SQLite схема и операции для проектов, целей, шаблонов, запусков и результатов.
- `internal/catalog` — загрузка индекса шаблонов и безопасный локальный кэш.
- `internal/template` — разбор Nuclei YAML, совместимость, оценка риска.
- `internal/dsl` — собственный вычислитель DSL-выражений Nuclei (лексер, Pratt-парсер, набор хелпер-функций). Без сторонних библиотек выражений и без внешнего бинарника.
- `internal/discovery` — DNS resolution, TCP connect, service/version probes и распознавание HTTP URL.
- `internal/engine` — собственный исполнитель Nuclei-шаблонов: HTTP-запросы, matchers (status/word/regex/dsl/size), extractors (regex/kval/dsl), ограничения частоты и параллельности.
- `internal/nse` — полный исполнитель NSE через Nmap и библиотеку nselib; встроенный gopher-lua остаётся ограниченным вариантом для окружения без Nmap.
- `internal/workflow` — соединение discovery, определения веб-сервисов и HTTP-движка.
- `internal/report` — JSON, HTML и CSV экспорт.
- `internal/tui` — интерфейс терминала: `tui.go` (модель, каталог проверок), `experience.go` (обработка клавиш), `view.go` (отрисовка), `jobs.go` (фоновые задачи), `launch.go` (сборка и запуск действий), `inventory.go` (накопленная картина хост → порты → находки по всем запускам проекта).

Приложение хранит базу и кэш шаблонов в пользовательском каталоге конфигурации ОС в подкаталоге `wscan`. Фоновые задачи существуют только в памяти текущего сеанса TUI: их результаты сохраняются в базу немедленно, но список самих задач и прогресс не переживают перезапуск.

## Текущие границы и безопасность

- TCP discovery использует TCP connect, а не SYN/raw сокеты; сканирование работает без повышенных привилегий.
- UDP-скан — best-effort и unprivileged: порт сообщается открытым только при ответе на пробу (для части сервисов есть протокольные пробы: DNS, NTP, SNMP, SSDP, остальным шлётся нулевой байт). «Тихий» порт = открыто|фильтровано и не показывается; закрытые (ICMP unreachable) не различаются надёжно без raw-ICMP (нужен root). То есть отсутствие UDP-находки не означает, что порт закрыт.
- Наборы портов Top-N читаются из `library/nmap/nmap-services`; при отсутствии файла — встроенный запасной список. `Все порты` (1–65535) выбирается вручную.
- `-sV`-подобная идентификация ограничена встроенными протокольными пробами и не равна полной базе сигнатур Nmap. На неизвестных протоколах возможны только имя порта и отсутствие версии; необычные сервисы могут быть классифицированы неверно.
- Успешное обнаружение открытого TCP-порта не доказывает, что на нём работает ожидаемый протокол.
- TLS fingerprinting не валидирует сертификат как браузер. Ошибка handshake оставляет запись сервиса с портом и предварительным именем.
- TCP discovery и протокольные проверки создают соединения и посылают запросы; выбранные проверки выполняются активно.
- Полный Nuclei загружает библиотеку исходных шаблонов. Совместимость загрузки не гарантирует результат на каждой цели: некоторые проверки требуют доступов, аргументов или дополнительных зависимостей.
- Ограниченный встроенный HTTP/DSL-движок применяется только при отсутствии полного Nuclei.
- Полный NSE запускается через Nmap с библиотекой nselib. Скрипты только с prerule/postrule не выполняются в задачах выбранного хоста/порта, поскольку не имеют такого скоупа.
- Ограниченный встроенный Lua использует песочницу. Полные движки запускаются отдельными процессами; отмена задачи завершает их группу процессов на Unix.
- Проверяйте только системы, на которые у вас есть разрешение.

## Следующие естественные расширения



- Расширить набор безопасных версионных probes и сигнатур, редактируемые списки портов, дополнительные движки обнаружения за интерфейсом `Discovery`.

## Полные движки и воздействие

При установленном Nuclei (проектный `bin/nuclei`, затем PATH) приложение исполняет выбранные полные шаблоны, включая payloads, pre-condition и fuzzing, через этот движок. Nmap исполняет NSE с библиотекой `library/nmap/nselib`, а не ограниченным набором Go/Lua модулей. Движки получают только выбранные шаблоны/скрипты и цели; отмена останавливает процесс и его дочерние процессы на Unix. JSONL Nuclei и XML Nmap превращаются в находки проекта. Ошибки сохраняются в результатах и журнале. Прогресс Nuclei отражает запросы текущего этапа, NSE — завершённые скрипты.

Внутри сервиса `Enter` открывает уровни «Обнаружение», «Активные проверки», «Сильное воздействие». Метаданные dos/intrusive/exploit/brute/fuzzing и конструкции payloads/fuzzing/code относятся к сильному воздействию. Все уровни могут отправлять сетевые запросы. Это классификация по метаданным, а не гарантия отсутствия побочных эффектов. Перед стартом и в журнале показываются выбранные уровни и количество проверок каждого уровня.

## Экран находки

`Enter` в колонке «Детали» при выбранной находке открывает полный текст с прокруткой; на порту `Enter` по-прежнему открывает проверки. В колонке находок `s` — проверки порта. Просмотр включает сохранённые URL, доказательства, описание, ссылки, имя матчера, протокол и запрос/ответ. Отсутствующие в исторических результатах поля не подставляются выдуманными данными.

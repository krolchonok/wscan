## Сборка из исходников — Linux x86-64

Нужны Go 1.26 или новее и Git. Для упаковки нужны Python 3, `tar` и `sha256sum`.

```sh
git clone https://github.com/krolchonok/wscan.git
cd wscan
CGO_ENABLED=0 go build -buildvcs=false -trimpath -ldflags='-s -w' -o wscan .
./wscan version
```

Без заданной версии команда покажет `wscan dev`. SQLite встроена; отдельный
сервер базы и C-компилятор не нужны. **Внешние Nuclei, Nmap и Metasploit не
используются.** YAML-шаблоны, NSE-скрипты и словари являются данными для нашего
движка. Обычные программы (`git`, `ping`, Python/Ruby, команды ОС) допускаются.
WinPEAS оставлен как отдельно согласованное исключение для ручной постэксплуатации.
[Проверка правила, возможности и ограничения](docs/ENGINE_POLICY_AUDIT.md).

### Получить полную библиотеку

Библиотека скачивается из отдельного репозитория, включая NSE и индексы.
При первом запуске приложение установит её автоматически. Можно скачать заранее:

```sh
./wscan library update
./wscan library status
./wscan
```

Локальная копия хранится в `~/.config/wscan/library/` и работает без интернета.
`internal/template/` содержит Go-парсер движка, а не библиотеку проверок.

Git нужен для обновления каталога. Python/Ruby и другие интерпретаторы нужны
только соответствующим `code:`-шаблонам, разрешаемым отдельно в настройках
проекта; Python 3 также используется передачей файлов MSSQL. Nmap устанавливать
не нужно: `library/nmap/` содержит скрипты, библиотеки и данные, а не внешний движок.

### Собрать архив для переноса

```sh
./scripts/package-linux-amd64.sh v0.2.0
```

Скрипт пересобирает приложение статически с указанной версией. Результат:

- `dist/wscan-v0.2.0-linux-amd64.tar.gz` — приложение и документация; библиотека скачивается отдельно;
- `dist/wscan-v0.2.0-linux-amd64.tar.gz.sha256` — контрольная сумма.

Путь установленной библиотеки можно задать через `WSCAN_LIBRARY_DIR`. Архив не
содержит бинарников Nuclei/Nmap/Metasploit или p0wny-shell. WinPEAS включён
как согласованное исключение и автоматически сканированием не запускается. На новом Linux-ПК
распакуйте архив и запустите `./start.sh`; Go там не нужен.
Общий `start.sh` открывает программу от root через sudo с текущими
настройками и базой проектов. Для Windows используйте отдельный ZIP; macOS этим архивом не поддерживается. [Перенос проектов](docs/TRANSFER.md).

### Тесты и следующий релиз

Для тестов скачайте отдельную библиотеку в рабочий каталог:

```sh
git clone --depth 1 https://github.com/krolchonok/wscan-templates.git library
CGO_ENABLED=0 go test ./...
```

Полный набор тестов и `go vet` проходит. Шесть прежних сбоев устранены:
[результат проверки](docs/KNOWN_TEST_FAILURES.md). Совместимость каталога
не гарантирует выполнение всех шаблонов на реальной цели.
После коммита и загрузки изменений создайте новый, ещё не занятый тег:

```sh
git push origin main
git tag v0.1.5
git push origin v0.1.5
```

GitHub Actions скачает библиотеку из её репозитория для тестов и
опубликует предварительный релиз со своим движком. Никакие внешние сканеры
не скачиваются и не запускаются. Результат тестов указан в описании релиза;
ошибки тестов или go vet блокируют публикацию. Actions собирает архив из тега.

# wscan

Модульный кроссплатформенный сканер веб-проверок. Первый прототип загружает HTTP-шаблоны в формате Nuclei YAML, управляет проектами через TUI и хранит цели, запуски и находки в локальной SQLite базе.

При ширине терминала от 88 колонок карточка показывает список находок слева и подробности справа. `↑/↓` в списке сразу обновляют подробности, `←/→` переключают панели; справа `↑/↓` прокручивают текст. На узком экране находки переключаются по `[` / `]`.

Карточка находки: `Tab` / `Shift+Tab` переключают «Обзор», «Доказательства» и «Рекомендации»; `r` открывает полный технический отчёт. `[` / `]` переходят к соседней находке, `Esc` возвращает туда, откуда открыта карточка: к хосту или к списку результатов. `↑/↓`, `PgUp/PgDn`, `Home/End` прокручивают текущий раздел; внизу указаны видимые строки.

`g` открывает задачи с выбором последней. Итог обнаружения показывает найденные хосты и открытые порты; `Enter` открывает их в панели хостов. При перелистывании хостов выбранный порт сохраняется по номеру и протоколу, даже если у промежуточного хоста его нет. Для отсутствующего порта показывается «не найден», затем выбор восстанавливается на следующем подходящем хосте.

Сведения AD Scan видны в основном фильтре результатов и в карточках соответствующих LDAP/Kerberos/DNS/SMB-портов. Сводка включает найденные домены, контроллеры и статус анонимного LDAP. RootDSE запрашивается также через LDAPS, когда доступны только 636/3269; ошибки соединения/чтения и отказ перечисления пользователей сохраняются явно. Старые результаты без диагностики LDAP нужно получить повторным AD Scan.

## Запуск

```sh
go run .
```

Для автоматизации: `wscan scan PROJECT_ID`. Экспорт запуска: `wscan export PROJECT_ID RUN_ID json|html|csv OUTPUT_PATH`.

Управление в TUI: `1` открывает отдельное окно подсетей, `2` — все хосты проекта, `3` — задачи. В списке проектов `d` запускает AD-аудит и создание проекта: выбери частную IPv4-подсеть активного интерфейса или введи CIDR вручную (в том числе маршрутизируемую VPN-подсеть). После успешного сканирования wscan автоматически создаёт и открывает проект с исходным CIDR, адресами найденных узлов, службами и результатами по ролям DC, Global Catalog, DNS, AD CS и Windows-хостам. Для AD CS проверяются стандартные HTTP(S) enrollment URL. Без учётных данных аудит также пытается прочитать LDAP-каталог (до 1000 пользователей), отмечает учётки с выключенным Kerberos pre-auth и SPN, а также признаки слабой конфигурации учёток: пароль не требуется, пароль не истекает, unconstrained delegation, обратимое хранение пароля, DES-only Kerberos и `adminCount=1`. Это предварительные признаки по LDAP-атрибутам, а не проверка возможности входа или фактических прав. Проверяются SMB null/guest и сохраняются видимые имена общих папок. Файлы, пароли и хеши не читаются; никаких изменений на узлах нет. Число адресов не ограничено: адреса обрабатываются потоком, скорость — до 250 TCP-проверок в секунду; окно показывает примерную длительность. Большие подсети могут сканироваться долго. `x` или `Esc` останавливает задачу. В окне подсетей `o` открывает только машины выбранного CIDR, а `Enter` — обнаружение и сканирование. Окно хостов показывает накопленные порты и результаты: от 128 колонок — три панели с расширенной областью результатов; от 88 — хосты слева, порты и результаты друг над другом; на узком или низком терминале — одна активная панель. Добавление и настройки сканирования открываются в компактных окнах по центру. Предпросмотр размеров: [макет интерфейса](docs/interface-preview.html). `←/→` (или `Tab`) переключают колонку, `↑/↓` двигают выбор внутри неё. В колонках «хосты» и «порты» сверху есть строки «Все в списке»/«Все порты» для действий сразу по всему набору. `Enter` открывает меню сканирования для текущего хоста, всех хостов (строка «Все в списке») или выбранного порта: обнаружение портов, Nuclei-проверки, Nmap NSE-скрипты или полный скан — каждое действие уходит в фон, интерфейс остаётся отзывчивым. `g` из любого экрана, кроме ввода текста, открывает задачи всех проектов: текущий этап, полоса прогресса, процент, число завершённых портов/проверок и время выполнения. `x` отменяет выбранную задачу, `Enter` открывает её подробности и журнал: точную область (хосты или один порт), выбранные проверки, этапы и ошибки. В подробностях `Enter` возвращает к результату на выбранном порту. Журналы новых задач сохраняются в `logs/scan-*.log` внутри каталога настроек `wscan`. Текущая задача видна в постоянной строке состояния. Панели занимают доступную высоту терминала и меняют размер вместе с окном. `a` — добавить хост, `d` — удалить выбранный хост, `r` — исправить повреждённый адрес, `t` — библиотека проверок проекта (используется действием «Полный скан»), `p` — настройки сканирования, `h` — история запусков, `e` — экспорт, `Esc` — назад к списку проектов. `?` — список клавиш.

AD-проход также проверяет TCP/139 (NetBIOS) и TCP/3389 (RDP). На доступных SMB-узлах собираются поддерживаемые диалекты, режим подписи и базовая ОС/доменная информация; на RDP — NTLM-метаданные имени и версии системы. Безопасная NSE-проверка MS17-010 ищет признаки уязвимого SMBv1 без эксплуатации. Другие проверки, которые могут повредить службу или загружают/выполняют код, в автоматический проход не входят. Отсутствие находки MS17-010 не является доказательством отсутствия уязвимости: проверка зависит от доступности SMBv1 и ответа сервера.

Если анонимный LDAP раскрыл домен и в диапазоне найден DNS-сервер, AD-аудит запрашивает стандартные SRV-записи LDAP, Kerberos, парольной службы и Global Catalog. Имена контроллеров сохраняются в находках проекта; адреса из SRV-ответов автоматически не сканируются. В конце прохода в проект добавляется компактная сводка узлов, сервисов, найденных учёток и риск-находок для навигации по первичной разведке; отдельный отчёт не создаётся.

Действие **Discover** открывает экран параметров: набор портов (Common / Top 100 / Top 1000 / Все 1–65535 / свой список вида `22,80,8000-8100`), TCP и/или UDP, и определять ли версии сервисов. Top-N берётся из `library/nmap/nmap-services` по частоте (как `nmap --top-ports`). UDP-скан — best-effort (порт считается открытым только если ответил на пробу; «тихие» порты не показываются, т.к. без raw-ICMP открыто|фильтровано не различить). Встроенный TCP connect scanner проверяет выбранные порты с ограниченными RPS и параллельностью, затем (если включено) выполняет ограниченное определение сервиса и версии (аналог `nmap -sV`) и запускает выбранные HTTP(S)-шаблоны на найденных веб-сервисах. Начальные пробы используют HEAD для HTTP, PING для Redis и приветственные баннеры. При неполном определении собственный движок применяет дополнительные пробы и все сигнатуры установленного nmap-service-probes (включая HTTP GET/OPTIONS). Полный диапазон TCP-портов выбирается в параметрах discovery. Настройки discovery и HTTP регулируются независимо. Выполняются выбранные вручную совместимые проверки. TCP connect и проверки сервиса создают сетевые подключения.

В списке проектов `Del`, `Backspace` или `Shift+D` открывает подтверждение удаления выбранного проекта. `Enter` удаляет проект и его данные из SQLite: цели, выбранные шаблоны, историю запусков, порты, находки и учётные записи; `Esc` отменяет. Активные задачи проекта нужно сначала остановить и дождаться их завершения. Общая библиотека шаблонов и экспортированные файлы отчётов сохраняются.

В списке хостов нажми `f` или `Space` на строке «Все в списке», чтобы выбрать все хосты, все живые, все с указанным открытым портом или очистить выбор. При выборе по порту открывается список найденных открытых портов с количеством хостов; стрелки и `Enter` выбирают порт. Доступен и ручной ввод. Формат порта: `445`, `443/tcp`, `53/udp`; без протокола используется TCP. Выбор ограничен текущим списком (включая открытую подсеть) и заменяет прежние отметки. Живыми считаются хосты с сохранёнными открытыми портами или ответами на обнаружение в текущей сессии. Новая проверка сети не запускается; при отсутствии совпадений прежний выбор сохраняется. `Enter` открывает действия для выбранных хостов.

Каталог синхронизируется с `projectdiscovery/nuclei-templates` по действию пользователя. Сохраняйте право на проверку целей.

**Проверки выполняет наш движок.** HTTP/TCP/DNS/TLS, DSL, payloads, workflows, `flow` и поддержанные JavaScript-модули реализованы внутри wscan на Go и встроенном goja. Шаблоны формата Nuclei не требуют бинарника Nuclei. Неподдержанные возможности должны отображаться в каталоге; полной совместимости с Nuclei нет.

Поиск портов и определение сервисов работают на Go. NSE-скрипты исполняются встроенным gopher-lua с нашими сетевыми модулями и совместимыми файлами `library/nmap/nselib`. Внешний Nmap не запускается. Поддержка NSE ограничена реализованными API и не равна всем возможностям Nmap.

Полное описание функций, порядка работы, хранения и ограничений доступно в [FUNCTIONS.md](FUNCTIONS.md).

## Архитектура

- `internal/domain` — модели проектов, шаблонов и находок.
- `internal/template` — YAML парсер и диагностика совместимости.
- `internal/engine` — HTTP исполнитель, matcher-ы, лимиты и параллельность.
- `internal/catalog` — синхронизация GitHub-каталога и локальный кэш.
- `internal/discovery` — собственное TCP connect обнаружение портов и ограниченное определение сервиса/версии по баннерам и безопасным протокольным запросам.
- `internal/workflow` — соединение обнаружения, поиска веб-сервисов и HTTP-проверок.
- `internal/storage` — SQLite репозиторий.
- `internal/report` — JSON, HTML и CSV.
- `internal/tui` — интерактивный интерфейс.

Настройки и база лежат в системном каталоге данных приложения `wscan`.

Для поиска имён по подсети: `1` → выбери CIDR → `Enter` → «Найти имена по PTR через DNS-сервер» → введи IP DNS-сервера (можно с портом, например `10.0.0.10:53`). Скан проверяет все адреса, включая адрес сети и broadcast, без ping; найденные имена сохраняются рядом с IP. Используются RPS и параллельность discovery, таймаут проекта; максимум 65536 адресов за запуск. Прогресс и отмена доступны в задачах (`g`, затем `x`). PTR-запись не подтверждает доступность хоста. Явные результаты сохраняются до следующего PTR-скана и не заменяются автоматическим системным DNS-поиском.

## Проверка внешнего скоупа

После поиска портов выбери хост или порт. На порту `Enter` сразу открывает проверки; на хосте выбери «Проверить найденные сервисы». Область запуска видна в выборе категорий и в сводке запуска. Проверки используют найденные порты.

Проверки хранятся в публичном репозитории `krolchonok/wscan-templates`, в папке `templates/`. На начальном экране проектов открой общие настройки (`p`) → «Библиотека шаблонов» → Enter: wscan скачает или обновит шаблоны в фоне. Раздел показывает состояние установки, количество YAML-шаблонов и файлов зависимостей, размер, папку, дату обновления и версию. Для скачивания нужен Git; авторизация в GitHub и `gh` не требуются. При ошибке скачивания прежняя библиотека сохраняется. URL можно переопределить через `WSCAN_LIBRARY_URL`.

```bash
wscan library update
wscan library status
```

Библиотека проверок развивается и публикуется в отдельном Git-репозитории; репозиторий софта содержит только приложение. Каталог кладётся в `~/.config/wscan/library`. В UI у категории видно «доступно / всего»: SMB включает все smb/samba NSE и связанные nuclei; «доступно» меньше, пока нативный движок не тянет `smb`/javascript.

Основная группировка — по сервису: Web, SMB, SSH, FTP, RDP, DNS, почта, базы данных и прочие. Проверки подбора учётных данных вынесены в отдельную группу на всех осях каталога; они не входят в массовый выбор сервиса или продукта. Выбирай их только явно из группы «Подбор учётных данных». `1` — по типу, `2` — по продукту, `3` — по сервису. Подходящая группа для выбранного порта подсвечивается; выбор остаётся ручным. `Enter` на сервисе открывает уровни воздействия: «Обнаружение», «Активные проверки», «Сильное воздействие». `Space` отмечает доступные проверки группы, `Enter` открывает отдельные шаблоны выбранного уровня. `End` переходит на строку «Запустить выбранные», `Enter` открывает сводку, ещё один `Enter` запускает задачу; `Esc` возвращает к выбору.

Каталог проверяется в фоне. В группах указано доступное и общее количество. Шаблоны, которые движок не умеет запускать (fuzzing/headless/javascript и т.п.), собраны в отдельной категории «Неподдерживаемые» — в Web/SMB/… они не попадают. Enter по этой категории показывает причины; при выборе группы берутся только доступные проверки. Загрузка не заменяет проверку на реальной цели: отдельные проверки могут требовать аргументы, доступы и дополнительные зависимости. Сервис показывает состояние последних проверок текущего сеанса; отсутствие находок само по себе не означает, что порт проверен.

Локальный прогон библиотеки без сетевых запросов и открытия базы проекта:

```sh
go run . audit-library reports/library-audit
```

Сводка находится в `reports/library-audit/README.md`, результат каждого шаблона — в `compatibility.json` рядом.

Уровень воздействия определяется по метаданным и конструкции шаблона. «Обнаружение» тоже отправляет запросы к сервису. «Сильное воздействие» включает fuzzing, brute force, эксплуатацию и DoS. Это ручной выбор конкретных проверок, не профиль проекта. Распределение выбранных проверок по уровням видно перед запуском и записывается в журнал задачи.

Источники полных движков: [Nuclei v3.11.1](https://github.com/projectdiscovery/nuclei/releases/tag/v3.11.1), [Nmap NSE](https://nmap.org/book/man-nse.html).

## Лимиты сканирования

Каталог предназначен для проверки удалённых хостов и сервисов. Локальные аудиты Windows/Linux и реестра, проверки локальных файлов и шаблоны `self-contained: true` исключены из выбора. Ранее сохранённые локальные проверки также блокируются при загрузке и запуске. Для code-шаблонов также проверяется наличие требуемого интерпретатора; если он отсутствует, каталог показывает конкретную причину. Эти проверки не заменяют проверку всех зависимостей и поведения шаблона во время выполнения.

**`code:`-шаблоны — единственное исключение из «только наш движок».** Они запускают настоящий внешний интерпретатор (`python3`/`ruby`/`bash`/...) прямо на машине сканера, не в песочнице. Выполнение выключено по умолчанию для каждого проекта; включить можно в настройках проекта (`p`, строка «code: внешний интерпретатор») — включение требует подтвердить отдельный экран-предупреждение, выключение подтверждения не требует.

Перед поиском портов строка «Добавлять» переключается `←/→`: открытые с определённым сервисом (по умолчанию) или все открытые, включая неизвестный сервис. TCP добавляется после успешного соединения, UDP — после ответа на пробу; закрытые и неподтверждённые порты не добавляются. Фильтр действует только на результаты нового поиска.

На рабочем столе `Delete` (или `d`) открывает подтверждение удаления: в колонке хостов — хоста, в колонках портов/деталей — выбранного порта. `Enter` подтверждает, `Esc` отменяет. При удалении хоста очищаются его порты и находки в рабочем списке, отменяются активные задачи с этим хостом. После повторного добавления хост пустой; старые результаты в него не подмешиваются. История запусков и доказательства доступны отдельно. Удаление отдельного порта сохраняется для рабочего списка проекта.

Названия TCP/UDP-портов берутся из `library/nmap/nmap-services`. Если протокол не определён ответом сервиса, название показывается с пометкой «по порту» и сохраняется отдельно в `port_service`. Такая подсказка не используется для автоматического выбора проверок или фильтра «с определённым сервисом». База также обогащает отображение старых результатов; изменения файла подхватываются при следующих обращениях. [Описание базы Nmap](https://nmap.org/book/nmap-services.html).

По умолчанию в окне сканирования выбраны все TCP-порты 1–65535 и добавление всех открытых портов, включая порты с неопределённым сервисом.

В параметрах сканирования `↑/↓` выбирают строку, `←/→` или `Space` переключают набор портов, TCP/UDP, определение версий и пресеты скорости (пресеты — по кругу). `Enter` на любой строке сразу запускает скан. `e` на строке набора портов открывает ввод своего списка, а на строках RPS/параллельности — ввод значения.

Для поиска портов есть отдельные пресеты: минимальный — 100 проб/с / 32 параллельно, средний — 1000 / 256, максимальный — 10000 / 1024, без лимита RPS — 0 / 2048. Выбор доступен в `p` и перед запуском поиска портов; там же можно ввести скорость и параллельность вручную. В сводке параметры относятся только к этому запуску и записываются в журнал. Лимит проб действует на TCP и UDP отдельно для каждого хоста, параллельность UDP ограничена 256. RPS 0 отключает задержку между пробами; параллельность остаётся конечной.

Пресеты скорости проверок доступны в `p` и в сводке запуска: минимальный — 5 RPS / 4 параллельно, средний — 50 / 16, максимальный — 200 / 64, без ограничений RPS — 0 / 128. RPS 0 отключает ограничение скорости запросов Nuclei и портовых проб Nmap; параллельность остаётся конечной и редактируется вручную. Пресеты меняют только RPS и параллельность проверок, сохраняя категории, таймаут, повторы и лимиты поиска портов. В `p` сохраняются значения проекта, в сводке — только конкретного запуска.

В сводке «Запуск проверок» перед стартом можно задать RPS, параллельность, таймаут и повторы только для этой задачи. `↑/↓` выбирают параметр, `Enter` открывает ввод, `Ctrl+U` очищает значение, `Enter` подтверждает. `Home` возвращает на строку запуска. Значения по умолчанию берутся из настроек проекта; изменения в сводке не сохраняются как настройки проекта и записываются в журнал задачи.

## Сканирование сетей и подсетей

В поле добавления цели можно указать IPv4/IPv6 CIDR, например `10.0.0.0/24`. Для подсети доступны ARP / ICMP / TCP host discovery и сканирование портов только отвечающих хостов. Опция `-Pn` отключает host discovery и сканирует все адреса диапазона. ICMP сначала использует непривилегированный сокет, затем raw ICMP при наличии прав и системный `ping`, если сокеты недоступны. TCP-ответ «соединение отклонено» тоже подтверждает доступность хоста. В Linux после проб учитываются подтверждённые соседи ядра (ARP на локальной сети); устаревшие, статические и неразрешённые записи не считаются живыми. На подтверждение уже начавшегося ARP-разрешения выделяется до 6 секунд. На других ОС поиск использует ICMP и TCP. Фиксированного ограничения на размер сети нет; время и память растут вместе с числом адресов. У IPv4 исключаются адрес сети и broadcast, кроме `/31` и `/32`. Фильтрация может скрыть хост, поэтому отсутствие ответа означает «не обнаружен», а не доказанное отсутствие узла.

После обнаружения хостов приложение в фоне запрашивает PTR-записи через системный DNS и показывает DNS-имена рядом с IP. Имена сохраняются в проекте и кешируются на час; если записи нет, отображается только IP. При изменении DNS-сервера система должна использовать DNS нужной сети.

После обнаружения можно запустить поиск портов на всех найденных хостах или отметить нужные строки клавишей `Space` и работать с выбранными хостами. В колонке портов выбери конкретный открытый порт, чтобы запустить выбранные шаблоны только на нём. `Space` на строке «Все в списке» сбрасывает групповой выбор.

Встроенный TCP-сканер повторно проверяет порты, не ответившие за время первого
прохода, и ошибки перегрузки: до 32 соединений одновременно, до 500 проб/сек
(или меньше, если выбран меньший лимит), таймаут не менее 1,5 секунды.
Повтор охватывает весь выбранный диапазон, включая нестандартные порты.
Подтверждённый `connection refused` повторять не нужно. Дополнительные пробы
учитываются в прогрессе; полный скан при потерях пакетов занимает больше времени.

Лимиты задаются на рабочем столе через `p`: RPS проверок, параллельность, таймаут, повторы и отдельные скорость/параллельность поиска портов. `↑/↓` выбирают настройку, `Enter` открывает ввод, `Ctrl+U` очищает старое значение, `Enter` сохраняет. Изменения действуют на новые задачи; запущенные задачи сохраняют параметры старта. Для Nmap RPS ограничивает портовые пробы, а не весь трафик NSE-скриптов.

## Подробности находок

Меню **5 Результаты** открывает полноширинный список: адрес, название и краткий вывод. По умолчанию фильтр «основное» показывает риски, ошибки и сводки Coerce. `i` показывает все сведения, `f` переключает фильтр, `/` ищет, `c` возвращает основной список. `Enter` открывает отдельную карточку с доказательствами; `Esc` возвращает к списку, `r` раскрывает технический отчёт.

`Space` отмечает результат, `a` отмечает/снимает все видимые строки. `Del`, `Backspace` или `d` предлагает удалить отмеченные результаты (без отметок — текущий); `D` — весь видимый список. `Enter` подтверждает, `Esc` отменяет. Удаление постоянно убирает детекты и их старые копии из базы текущего проекта, включая историю. Хосты, службы и другие проекты сохраняются. Уже экспортированные файлы не изменяются; последующая проверка может обнаружить результат снова.

Этапы Coerce/Responder объединены в одну сводку на машину. Вывод строится по последнему сохранённому отчёту Coerce; старое успешное событие не превращает более новый отказ в успех. Полный журнал остаётся в технической карточке. Удаление сводки удаляет и входящие в неё события.

Результаты разделены по смыслу: риски, сведения о сервисе и ошибки проверок. Информационные результаты не считаются уязвимостями. В рабочем списке одинаковые результаты одной проверки и адреса показываются один раз, по последнему сохранённому совпадению; история остаётся полной. Для SMB в деталях порта показаны версии, согласованная версия соединения, SMBv1, подпись, имя машины и сообщённая версия ОС — только при наличии сохранённых доказательств. Поле шифрования отдельного соединения не выдаётся за настройку всего сервера.

Карточка `Enter` сначала показывает смысл результата и доказательства; `r` раскрывает технические данные, описание шаблона и сохранённые запрос/ответ. Ошибки NSE не сохраняются как находки; исторический вывод `ERROR:` отображается как ошибка. Для старого результата NSE без порта привязка восстанавливается, если в сохранённом запуске для этого хоста был ровно один сервис. FTP-проверки группируются в FTP, включая проверки Sambar.

На рабочем столе выбери хост и порт, перейди в колонку «Результаты» и нажми `Enter` на находке. Откроется общий экран результатов с областью выбранного хоста или порта. Из истории `Enter` открывает только выбранный запуск; из задачи — её сохранённый запуск. Просмотр, поиск, фильтры, карточки и удаление одинаковы во всех этих входах. Область указана в заголовке и не меняется от обновления другого скана. `Esc` из карточки возвращает к списку, следующий `Esc` — к исходному экрану; `5` открывает весь проект. В задачах по умолчанию показан итог; `r` раскрывает журнал. `?` показывает прокручиваемую помощь для текущего экрана.

Новые результаты Nuclei сохраняют также описание, ссылки, имя матчера, протокол и переданные движком запрос/ответ. Если в старой находке нет описания, карточка читает описание проверки и ссылки из локальной библиотеки, отдельно от доказательств скана. Несохранённые запросы и ответы восстановить без повторного скана нельзя. Адреса HTTP/HTTPS без явного порта сопоставляются с 80/443, а не теряются из списка порта.

Отсутствующий или пустой `.nuclei-ignore` заполняется корректным YAML при подготовке Nuclei; существующие пользовательские исключения не меняются. NSE-скрипты только с prerule/postrule отмечаются недоступными для выбранного хоста/порта, поскольку выполняются вне такого скоупа. Завершённые задачи с ошибками проверок помечаются «готово с ошибками» и учитываются в строке состояния.

### Сканирование WinRM

В группировке по сервисам появилась отдельная категория **WinRM**: обнаружение сервиса, объявленные методы аутентификации, Basic по HTTP и объявленный CredSSP. Проверки отправляют POST `/wsman` без учётки и не выполняют команды. Basic/CredSSP в challenge не подтверждают успешный вход или CVE. HTTPS выбирается для 5986 и сервисов с TLS; нестандартный порт сохраняется.

[Покрытие и план аудита WinRM](library/security/winrm-checks.md): TLS, настройки с учёткой, границы подтверждения CVE.

### WinRM в меню взаимодействия

На выбранном хосте нажмите `i`, выберите **WinRM** и нажмите Enter.
В форме подключения выберите сохранённую учётку с паролем; `c` открывает
Credentials, где `a` добавляет новую. Esc возвращает к подключению.
`s` переключает HTTP/HTTPS, `p` задаёт порт, `t` переключает проверку
сертификата. По умолчанию сертификат HTTPS проверяется. NTLM-хеши в этом
режиме пока не поддерживаются.

После входа отображаются пользователь, группы и привилегии. Esc открывает
проводник: Enter — каталог или предпросмотр файла, ← — родительский каталог,
`d` — скачать, `a` — полный ACL выбранного объекта, `p` — перейти по пути,
`e` — экспортировать список в CSV, `r` — обновить. Файлы и CSV сохраняются
в `downloads` в каталоге настроек wscan.

`c` выполняет одну PowerShell-команду в каталоге проводника и показывает
вывод, stderr и код завершения. `s` открывает PowerShell-сессию: Enter или
`c` вводит очередную команду, каталог и переменные сохраняются между
командами. Esc закрывает сессию; отмена выполняющейся команды также закрывает
её. Вывод можно прокручивать ↑/↓, PgUp/PgDn и Home/End.

Для проверки на настоящей Windows предусмотрен тест
`TestWinRMWindowsIntegration`. Он запускается только при явно заданном
`WSCAN_TEST_WINRM_HOST`; учётка задаётся переменными `WSCAN_TEST_WINRM_USER`,
`WSCAN_TEST_WINRM_PASSWORD` и, при необходимости, `WSCAN_TEST_WINRM_DOMAIN`.
Дополнительные параметры — `WSCAN_TEST_WINRM_PORT` и
`WSCAN_TEST_WINRM_INSECURE=1` для самоподписанного сертификата.

## MSSQL, SMB и Web LFI

После подключения MSSQL меню действий включает чтение базы/таблиц, проверку sysadmin и управление xp_cmdshell. Для передачи файла выберите **Передать файл через HTTP (Python)**: локальный путь, наш IP для Windows-хоста (обычно VPN), TCP-порт (8000 по умолчанию), путь назначения на Windows. Нужен `python3`; сервер отдаёт копию одного файла, проверяется SHA-256 на Windows, после передачи/отмены сервер закрывается. Существующий файл назначения не перезаписывается. Передача и команды выполняются через xp_cmdshell и требуют AllowExploit, включённого xp_cmdshell и прав текущей учётки.

**Запустить WinPEAS** принимает путь к уже переданному EXE, запускает его в фоне с `notcolor`, возвращает PID и сохраняет stdout в `<путь EXE>.txt`, stderr в `<путь EXE>.stderr.txt`. Старые отчёты не перезаписываются. **Прочитать отчёт** открывает первые 400 строк; **Следующие 400 строк** листает дальше. Полный отчёт остаётся на Windows. Через тот же пункт можно прочитать stderr или другой текстовый файл. Для возврата к началу снова выберите чтение отчёта. Завершение сеанса MSSQL не останавливает запущенный WinPEAS.


`i` на хосте/сервисе → **Взаимодействие** → MSSQL: выбрать одну учётку и порт, Enter подключиться. Domain включает Windows NTLM; пустой Domain — SQL login. `1`–`8` запускают фиксированный аудит, `b` меняет базу, Enter открывает меню действий, `c` открывает SQL batch (требуется AllowExploit), `n` — ограниченный выбор NSE с этой учёткой. Сессия сохраняется; Esc закрывает её. TLS и проверка сертификата задаются в форме подключения.

В SMB: `a` переключает null/guest, `c` выбирает учётку (пароль/NTLM-хеш), `p` порт, `f` ищет конфигурации в выбранной шаре. Проверки права записи больше не выполняются обычным проводником; WRITE остаётся неизвестным. Web LFI задаёт один URL/параметр/virtual host и выполняет до четырёх запросов без редиректов и внешних callback (AllowExploit).

Подробности и список для ручной проверки: [library/security/external-audit-implementation.md](library/security/external-audit-implementation.md). Новая сборка: `./wscan-external-audit`; исходный бинарник `./wscan` не заменён. Тесты и проверки на целях при реализации не запускались.

### Перебор Telnet

`telnet-brute.nse` выполняется нативной последовательной реализацией wscan,
без неподдерживаемого планировщика Lua-корутин. Сначала проверяется имя
пользователя как пароль (`root/root`), затем словарь. Лимит попыток на имя
в одном запуске берётся из настройки проекта LockoutMaxAttempts (по умолчанию 3,
максимум 100); успешные имена дальше не перебираются. RPS, задержка и отмена
сохраняются. Между запусками этот NSE-лимит не хранится; учёт истории попыток
и окна блокировки действует в отдельном режиме сохранённых credentials (`x`).
Этот режим теперь поддерживает Telnet, включая обнаруженные сервисы `tcp/telnet`.

Согласование Telnet и разорванные на пакеты приглашения обрабатываются до
передачи логина/пароля. Успех определяется по shell prompt после пароля;
отказ распознаётся отдельно, неизвестный ответ/таймаут считается ошибкой.
Команды не выполняются, пароль в NSE-результате не выводится.
TLS Telnet (992/telnets) не поддерживается: пароль открытым текстом туда не отправляется.
Проверено на локальных тестовых серверах; реальный хост не сканировался.

### FTP в меню взаимодействия

На выбранном хосте нажмите `i` → **FTP**. Если выбран FTP-порт, он подставляется
в форму подключения, включая нестандартный. Enter подключается как anonymous;
↓ выбирает сохранённую учётку с паролем. `c` открывает Credentials, `p` меняет
порт, `s` переключает FTP → FTPS (AUTH TLS) → FTPS (implicit TLS).
`t` переключает проверку сертификата; по умолчанию она включена.

В проводнике: Enter — каталог или предпросмотр файла, ← — родительский каталог,
`p` — перейти по пути, `d` — скачать, `e` — экспортировать список в CSV,
`r` — обновить, `c` — выбрать другую учётку. Предпросмотр ограничен 64 КиБ;
двоичные файлы отображаются в hex. Скачивание показывает прогресс и скорость;
Esc отменяет операцию, незавершённый локальный файл удаляется. Файлы и CSV
сохраняются в `downloads` в каталоге настроек wscan.

Проводник выполняет чтение: PWD/CWD, MLSD или LIST, RETR. Использует пассивные
соединения EPSV/PASV; адрес данных привязан к серверу управляющего соединения.
В FTPS защищены и управляющее, и соединение данных. Символические ссылки
показываются отдельно; для перехода к их цели используется ввод пути.
Показаны максимум 1000 записей; ответ списка ограничен 4 МиБ. Вход учитывает
лимит ошибок учётки; FTP не принимает NTLM-хеши.

Проверено на локальных FTP/FTPS-серверах: вход, отказ в доступе, MLSD/LIST,
предпросмотр, скачивание, сертификаты, отмена и защита от подмены PASV-адреса.
Клиент: [github.com/jlaffaye/ftp](https://pkg.go.dev/github.com/jlaffaye/ftp), v0.2.4.

Проверки анонимного доступа, пустых паролей и стандартных учёток БД: [покрытие и ограничения](library/security/database-access-checks.md).

## Python и Ruby

На начальном экране проектов открой общие настройки (`p`) → «Зависимости: Python и Ruby». Панель показывает версии и пути найденных интерпретаторов. Выбери отсутствующий интерпретатор и нажми Enter: wscan покажет команду установки для Linux/Homebrew или откроет официальную страницу загрузки для Windows и систем без поддерживаемого менеджера пакетов. Подтверди установку Enter; пароль sudo вводится в терминале установщика. После установки статус и доступность шаблонов обновляются. `r` повторно проверяет интерпретаторы.

Общие настройки доступны до выбора проекта и управляют библиотекой и интерпретаторами для всей программы. В открытом проекте `p` открывает его собственные настройки скорости, таймаутов, поиска портов и разрешений.

Удалённый доменный сбор **BloodHound CE** доступен в AD-взаимодействиях:
LDAP/LDAPS с машины wscan, без запуска коллектора на Windows-целях.
Профиль, ограничения и импорт ZIP: [BLOODHOUND.md](docs/BLOODHOUND.md).
